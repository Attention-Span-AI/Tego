# Gaps, drawbacks and risks

Revised 2026-11-17. Every item that is ours to fix now names the decision that closes it (ADR, spec section or feature id). Section A items are stated limits with their mitigation. Sorted from things that cannot be fixed to design gaps.
"Do" is the mitigation or the decision still owed.

ADR 0144 slices 2 to 6 provide the immutable baseline snapshot, one compiler materializer,
dual hashes, compiled-grant conflicts, topology/coverage checks, owner-layer protection,
self-contained records, receipts and validated historical insertion. Conflict checks cover
compiled home/relative/link spellings and known aliases, not a different filesystem instance
showing the same data (C71). Empty/absent baseline JSON omits effective_hash. Enforcing launches
with a nonempty baseline remain refused until slice 9 proves the actual mechanisms. The reviewed
base35 fixes are integrated. Editing remains slices 7 and 8. Baseline enforcement and governed
layer changes are owed in a guest.
Decision loads refuse unsafe/invalid layers; observation and stop report UNKNOWN with its cause.
Automatic adoption guards reload trusted layers and compile each fresh owner adoption. Preparation and
final admission use one table of named admission checks. After the host-wide migration-lock wait, final
admission runs every check in the table marked rechecked, including the chain-anchor file probe, selected-layer
identities and exact bytes, baseline digest including emptiness, and owner/placement checks before any process
moves. Snapshot entries retain compiled contract choices, selected mechanism/probe results/prepared descriptors,
immutable boot facts, and the recording-only target home, which admits no file boundary. The run-directory
contract check is derived from the compiled contract snapshot. The skip-counter baseline stays fixed so
skips during the migration-lock wait remain counted. For each actual adoption, own-directory
initialisation precedes the strict snapshot load used for compilation, so first use keeps that snapshot current.
A failed rechecked entry refuses and cleans up; already adopted runs keep their snapshots. A record directory
that changes resolved placement or device/inode identity requires restart. Supported absence pins the existing
ancestor and missing suffix until creation. These are boundary checks, without continuous directory custody.
Fresh backend selection, live plane checks before arming and after the migration-lock wait, and
recording-only handle changes also affect empty-baseline adoptions;
the nonempty-baseline launch gate does not prove those ordinary paths. Base/head ordinary-adoption
guest checks cover 39 positive rows in each of two LSM contexts, including a targeted repair in the
default context. The record-location table accepts all 12 local checks without refusal; its
network-home row models stable identity locally. A real network-mounted home remains owed in a guest.
The saved live-mode guest rows change admission before the agent starts. Admission changing after
selection, with refusal, cleanup and no movement, remains owed in a guest.
The property checks decision tightening, with separate refusal and ask counts; a reason may change
only to the baseline entry's own reason for the action. Its finite corpus uses fixed baseline choices and
synthetic mount topology; it does not generate arbitrary baseline combinations, successive nonempty-baseline
changes, system-only absent targets or mutations during admission.

## A. Structural limits: state them, do not promise around them

| # | Limit | Why it cannot be fixed | Do |
|---|-------|------------------------|----|
| A1 | **Every allowed endpoint** is an always-open exfiltration channel, not only the model endpoint. Anything the agent can read it can put in a prompt — or in a commit, or in a POST to an allowed tool host. Both published incidents of this shape left through `github.com:443` on the developer's own token rather than to an attacker-controlled host: Invariant Labs' GitHub MCP "toxic agent flow" (May 2025), where a malicious issue in a public repository drove the agent to publish private-repository contents into a public PR, and the nx `s1ngularity` compromise (August 2025), which pushed harvested credentials to newly created public repositories in the victim's own account. | Every endpoint the agent works through must be allowed or the agent does nothing. Ordinary socket grants match `host:port`; supported declared-forwarder HTTP rules additionally constrain method/path (A4), while permitted requests can still carry data. | Default read-deny for secret paths (E10). Tego is not data-loss prevention, and that holds for *every* allowed endpoint, not just the model one. **Current:** E10 deny_read and E56 watch narrow or record the supported input paths. No promise that copies of watched files are blocked is made. `fs.deny_read`/`fs.watch` are what narrow the reach; at tiers 2 and 3, or under `record: full`, the record shows what was read before what left. |
| A2 | An allowed interpreter can do anything in-process. `exec.allow: [python]` gates subprocess names, not behaviour. | Kernel sees processes and syscalls, not Python objects. | Threat model: kernel rules hold against a mistaken or injected agent for files, network and **exec of new binaries by path**; they do not stop in-process logic. "Exec of new binaries" was two claims with a seam between them (C30/C31). In tiers 1–2 the seccomp supervisor now decides every exec on the file it resolves and refuses what no entry grants, which covers an **anonymous image** (a memfd, an `anon_inode:`, an unlinked file) Landlock's `file_open` does not govern and a **directly-invoked loader**. The main anonymous vector, an executable **memfd**, is closed race-free where exec is restricted: the seccomp filter refuses at creation a `memfd_create` without `MFD_NOEXEC_SEAL` or with `MFD_HUGETLB` where the kernel honours the flag, and every `memfd_create` on a kernel without it, a probe deciding which (C30). The supervisor's walk is *best-effort* for the rest — a memfd received from outside the run, and the supervisor's finer decisions inside the granted set (`exec.deny`, `exec.ask`, command rules, live blocks, the MCP gate) — because it decides on a path or descriptor the kernel resolves again after `CONTINUE`: **any** thread or `CLONE_FILES` child can swap the descriptor, and **any** concurrent process able to write a directory on the path (not only a thread of the agent) can repoint a symlink, between the decision and that re-lookup, and the kernel then runs another file, but never one outside the files `exec.allow` grants as the exec's image (tier 1's Landlock `EXECUTE` set bounds it; what a granted interpreter runs in-process is this row's A2, and a granted loader's target is C31); a ready kernel decision plane's `bprm_check_security` is race-free (C30). Executable-mapping policy requires the actual `mmap_file`/`file_mprotect` decision hooks, available in a ready tier-2 or tier-3 plane (C31); tier 1 and the fanotify fallback retain the documented residual. **E69 language-level sources** (PEP 578 / Node preload) are unimplemented future product work; no in-process call-stack recording is promised. |
| A3 | Capture is only as good as TLS linkage. Bundled BoringSSL, rustls, gRPC, or an agent that ignores the base-URL variable are enforce-only. | Uprobes need a symbol; the forwarder needs cooperation from the client's config. | Gap line per run (E25, S8); forwarder bypass is refused by net.allow so it is visible, not silent. **Current:** E22 forwarder and supported symbol-based TLS uprobes. **E71 static-TLS symbol recovery** remains unimplemented future product work; missing symbols must remain visible as a capture gap. |
| A4 | Raw socket rules govern destinations and transport rather than HTTP use. | The kernel sees the socket, not the HTTP request. | **Mitigated for declared forwarders:** E59 `net.http` checks each authenticated HTTP/1.1 or HTTP/2 method and path before forwarding. It requires explicit forwarder capture and coverage of every declared model listener. Direct socket grants still admit arbitrary content to an allowed peer. |
| A5 | Effects inside systems that never run under Tego (SaaS, managed DB) are invisible. | Nothing runs there. | Propagated identity (E44) so the other side's logs can be joined. **→** **Partly mitigated**: E44 identity propagation. Boundary events (E46) are not built. |
| A6 | Everything is per host. | Kernel enforcement is local by nature. | **Stated**: Tego has no cross-host view. |
| A8 | Work handed to a daemon is enforced and recorded only where kernel programs are keyed by cgroup (root tiers); tier 1 sees the API boundary only. | Landlock and seccomp follow process lineage, not cgroups. | Capability matrix per run. **→ Stated.** Proxy `boundary` events (E43, E46) are designed, not built. |
| A9 | A Landlock domain with fs rights refuses every `mount`, `umount`, `move_mount`, `remount` and `pivot_root` (verified in `security/landlock/fs.c` and by `bwrap` on the test machine), so rootless podman/buildah, bubblewrap, `unshare -m` and agent-started sandboxes do not run in tier 1; setuid `newuidmap` is neutered by `no_new_privs`. | Kernel rule with no access right to grant it. | Refuse and record `gap why=landlock-topology`; `compile` warns. **→ Stated:** refused and recorded; `containers: rootless` (E43b) is not built. |
| A13 | *Added 2026-11-01 (ADR 0128).* A run can read the host's network: interface names and MAC addresses, every address (LAN and VPN), routes, and the neighbour table (other machines on the LAN). A run cannot change any of it: no process of a run under a `net:` section holds `CAP_NET_ADMIN`. |
| A7 | `no_new_privs` is required by seccomp and Landlock, so setuid binaries inside the run do not work (`sudo`, some `mount` paths). *Amended 2026-09-24 (ADR 0033):* at every tier by default now, the root tiers included; a root-tier contract's `setuid: true` opts out, with a compile warning. | Kernel rule. | **Stated limitation:** the root-tier `setuid` opt-in is implemented, with the documented warning.
