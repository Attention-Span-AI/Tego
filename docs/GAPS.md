# Gaps, drawbacks and risks

Revised 2026-11-05. Every item that is ours to fix now names the decision that closes it (ADR, spec section or feature id). Section A items are stated limits with their mitigation. Sorted from things that cannot be fixed to design gaps.
"Do" is the mitigation or the decision still owed.

## A. Structural limits: state them, do not promise around them

| # | Limit | Why it cannot be fixed | Do |
|---|-------|------------------------|----|
| A1 | **Every allowed endpoint** is an always-open exfiltration channel, not only the model endpoint. Anything the agent can read it can put in a prompt — or in a commit, or in a POST to an allowed tool host. Both published incidents of this shape left through `github.com:443` on the developer's own token rather than to an attacker-controlled host: Invariant Labs' GitHub MCP "toxic agent flow" (May 2025), where a malicious issue in a public repository drove the agent to publish private-repository contents into a public PR, and the nx `s1ngularity` compromise (August 2025), which pushed harvested credentials to newly created public repositories in the victim's own account. | Every endpoint the agent works through must be allowed or the agent does nothing. Ordinary socket grants match `host:port`; supported declared-forwarder HTTP rules additionally constrain method/path (A4), while permitted requests can still carry data. | Default read-deny for secret paths (E10). Tego is not data-loss prevention, and that holds for *every* allowed endpoint, not just the model one. **Current:** E10 deny_read and E56 watch narrow or record the supported input paths. No promise that copies of watched files are blocked is made. `fs.deny_read`/`fs.watch` are what narrow the reach; at tiers 2 and 3, or under `record: full`, the record shows what was read before what left. |
| A2 | An allowed interpreter can do anything in-process. `exec.allow: [python]` gates subprocess names, not behaviour. | Kernel sees processes and syscalls, not Python objects. | Threat model: kernel rules hold against a mistaken or injected agent for files, network and **exec of new binaries by path**; they do not stop in-process logic. "Exec of new binaries" was two claims with a seam between them (C30/C31). In tiers 1–2 the seccomp supervisor now decides every exec on the file it resolves and refuses what no entry grants, which covers an **anonymous image** (a memfd, an `anon_inode:`, an unlinked file) Landlock's `file_open` does not govern and a **directly-invoked loader**. The main anonymous vector, an executable **memfd**, is closed race-free where exec is restricted: the seccomp filter refuses at creation a `memfd_create` without `MFD_NOEXEC_SEAL` or with `MFD_HUGETLB` where the kernel honours the flag, and every `memfd_create` on a kernel without it, a probe deciding which (C30). The supervisor's walk is *best-effort* for the rest — anonymous images that arrive another way, and the directly-invoked loader — because it decides on a path or descriptor the kernel resolves again after `CONTINUE`: **any** thread or `CLONE_FILES` child can swap the descriptor, and **any** concurrent process able to write a directory on the path (not only a thread of the agent) can repoint a symlink, between the decision and that re-lookup; a ready kernel decision plane's `bprm_check_security` is race-free (C30). Executable-mapping policy requires the actual `mmap_file`/`file_mprotect` decision hooks, available in a ready tier-2 or tier-3 plane (C31); tier 1 and the fanotify fallback retain the documented residual. **E69 language-level sources** (PEP 578 / Node preload) are unimplemented future product work; no in-process call-stack recording is promised. |
| A3 | Capture is only as good as TLS linkage. Bundled BoringSSL, rustls, gRPC, or an agent that ignores the base-URL variable are enforce-only. | Uprobes need a symbol; the forwarder needs cooperation from the client's config. | Gap line per run (E25, S8); forwarder bypass is refused by net.allow so it is visible, not silent. **Current:** E22 forwarder and supported symbol-based TLS uprobes. **E71 static-TLS symbol recovery** remains unimplemented future product work; missing symbols must remain visible as a capture gap. |
| A4 | Raw socket rules govern destinations and transport rather than HTTP use. | The kernel sees the socket, not the HTTP request. | **Mitigated for declared forwarders:** E59 `net.http` checks each authenticated HTTP/1.1 or HTTP/2 method and path before forwarding. It requires explicit forwarder capture and coverage of every declared model listener. Direct socket grants still admit arbitrary content to an allowed peer. |
| A5 | Effects inside systems that never run under Tego (SaaS, managed DB) are invisible. | Nothing runs there. | Propagated identity (E44) so the other side's logs can be joined. **→** **Partly mitigated**: E44 identity propagation. Boundary events (E46) are not built. |
| A6 | Everything is per host. | Kernel enforcement is local by nature. | **Stated**: Tego has no cross-host view. |
| A8 | Work handed to a daemon is enforced and recorded only where kernel programs are keyed by cgroup (root tiers); tier 1 sees the API boundary only. | Landlock and seccomp follow process lineage, not cgroups. | Capability matrix per run. **→ Stated.** Proxy `boundary` events (E43, E46) are designed, not built. |
| A9 | A Landlock domain with fs rights refuses every `mount`, `umount`, `move_mount`, `remount` and `pivot_root` (verified in `security/landlock/fs.c` and by `bwrap` on the test machine), so rootless podman/buildah, bubblewrap, `unshare -m` and agent-started sandboxes do not run in tier 1; setuid `newuidmap` is neutered by `no_new_privs`. | Kernel rule with no access right to grant it. | Refuse and record `gap why=landlock-topology`; `compile` warns. **→ Stated:** refused and recorded; `containers: rootless` (E43b) is not built. |
| A13 | *Added 2026-11-01 (ADR 0128).* A run can read the host's network: interface names and MAC addresses, every address (LAN and VPN), routes, and the neighbour table (other machines on the LAN). Under any contract, with no key to turn it off. | `send(2)` and `write(2)` on a route socket reach the kernel with no notification, so a filter could only keep this by refusing `socket(AF_NETLINK)`, which breaks Node, Go and glibc; most of it is in `/proc/net` and `/sys/class/net` too. | Stated, in ADR 0128, OPERATIONS and every contract's Always on rules. A run cannot change any of it: no process of a run under a `net:` section holds `CAP_NET_ADMIN`. |
| A7 | `no_new_privs` is required by seccomp and Landlock, so setuid binaries inside the run do not work (`sudo`, some `mount` paths). *Amended 2026-09-24 (ADR 0033):* at every tier by default now, the root tiers included; a root-tier contract's `setuid: true` opts out, with a compile warning. | Kernel rule. | **Stated limitation:** the root-tier `setuid` opt-in is implemented, with the documented warning. E70 ask-gated privileged commands remain unimplemented: nonempty `exec.privileged` is rejected. A separate privileged helper requires its own authorization and contract. |
| A11 | *Amended 2026-11-03 (ADR 0069, SEC09/SEC10).* Held reads retain launch-nested target identities, including denied descendants, and refuse reads through renamed or hard-linked aliases. A file put at a protected name or in a denied directory later is pinned in turn; a change that cannot be followed fails closed. Both hold for human-selected alternates and for approvals of the supervisor's own pin (`fs.ask`, `fs.ask_read`, a copied gate's ask). | An install that cannot be followed (deleted or moved out of sight before the queue is read, two installs of one name, a directory at a launch name, a replaced ancestor), losing a watch, overflowing its queue, or a mount change that moves a protected place (a work volume unmounted, a mount over the project) refuses all held reads until restart (`held-read-identity-unknown`); a mount change made and undone between two held reads is not seen, so the mount topology of the protected places is a support condition. A directory made under a new name in a denied directory is not followed. Launch refuses missing/unreadable targets, unsupported filesystem views, including duplicate identities (remote, FUSE, overlay or unknown), or the 8,192 visited-name/watch bound. The list holds the protected objects, each target's parent and each denied directory; the directories above may also be overlayfs, so a container with an overlay `/` and the project on a local volume holds its reads, and a project in the image layer, on a network or FUSE share or on ZFS is refused at launch. A future name-only match outside watched launch targets is outside this identity snapshot until a held read pins it. At tier landlock with held reads and a broad writable parent, a protected file installed after compile can be renamed, exchanged (`renameat2(RENAME_EXCHANGE)`) or hard-linked from covered `sub/.env` to uncovered `target/.env`, then read there, when neither name is a watched launch target and no earlier held read pinned the source. Moving a directory containing a future declared glob match out of its glob scope has the same residual. Measured 2026-11-05 in Fedora 7.0 KVM with explicit held reads: file rename, exchange, hard link, dirfd-based `linkat`, and a directory move carrying a future declared token each exited 0 and read the alias. This predates the rejected coverage extension; landlock has no root-tier name-mutation floor. Launch-pinned files, watched installations and names still covered at the destination are not this counterexample; root-tier name checks have different coverage. Device and label residuals remain; the earlier per-open measurements predate these checks. | Restart after an uncertain change. Keep secrets outside writable folders to avoid held-read cost (and, in a container, to run at all with the project in the image layer: put it on a named volume or a local bind mount; or `fs.reads: direct`, unenforced). `fs.deny_read.moved` now covers launch-nested targets when held reads are served; it does not claim an identity snapshot of all future glob matches. Automatic recovery after replacements and broader name-scope identity tracking remain work. |
| A12 | *Added 2026-10-26.* At tier landlock a `deny_read` freezes the readable tree around it at launch: a directory or file made, or a listed file replaced, beside any ancestor of an enforced target after the run started is unreadable for the rest of the run, everything beneath it too. With the built-in `~/.ssh` entry `$HOME` is such an ancestor, so a new top-level entry in `$HOME` is one. | Landlock is an allow-list whose domain takes no new rule after `landlock_restrict_self`; the target's ancestors get `READ_DIR` only and their siblings are granted by one listing (enforce-landlock R3, E10). | **Recorded truthfully:** the supervisor refuses such a read or exec itself with the kernel's `EACCES`, line `refused`, `read-denied`, rule `deny-read-snapshot` (it said `allow` before), wherever opens are notified (`record: full`, held reads, an `fs.ask_read` or a read gate). A listing of the new directory still works. Remedy: restart the run, or keep what a long run must read beneath a directory that existed at launch. Not built: `run_start` naming the frozen ancestors; the root tiers' inherited ruleset is not wired or verified. |
| A10 | *Added 2026-09-24.* A `deny_read` directory at tiers 1 and 2 hides its files' contents, not their names or activity: `ls` lists it through the `READ_DIR` it inherits from the nearest granting ancestor, and an inotify or unprivileged fanotify watch on it reports which of its files are opened and changed. Reproduced. | Landlock's `READ_DIR` is a right of the directory the rule lands on, inherited by every directory beneath it that no rule narrows, and a `deny_read` denies by granting nothing; neither watch API is a Landlock hook or a syscall the filter notifies. | State it (SEMANTICS §1). A secret whose name must stay hidden goes outside every readable tree. **Condition:** refusing `inotify_add_watch` and `fanotify_mark` on a path under a `deny_read` target in the supervisor would hide activity, best effort against a racing path, as `deny_write` is; not built. **Built 2026-11-02** (supervisor R36, enforce-landlock R11e): every enforcing run's filter notifies `inotify_add_watch`, `fanotify_mark` and `fcntl(F_NOTIFY)`, and the supervisor refuses, `EACCES` with a refused line, a watch of a `deny_read` target or anything beneath it (reached by name, link, `..` or descriptor), a live read or path block or an unlifted read fence entry; a whole-mount or filesystem `fanotify` mark is refused `EPERM`. Still open: the names in a listing; a file target's own activity seen through a watch of the directory that holds it; the check is best effort on the copied name or descriptor (a racing thread can redirect a watch). |

B5 correction (2026-11-05): the RHEL 9 target and the release's Kernel minimums did not prove v0.1.0's
`net.listen` coverage. Its root-tier listener controls failed preparation on RHEL 9's 5.14 with
`attach tego_bind_result: cannot create bpf perf link: permission denied`. The bind/listen outcome programs
already existed (introduced 2026-10-04); the wrong CO-RE type moved their return read outside the individual
syscall event. The same mistake disabled optional exec outcome links. Using `syscall_trace_exit` corrects all
four hooks without dropping listener cleanup, terminal results or any enforced property. Outbound-only networking
did not require the listener hooks. This is a correction to the historical coverage claim, not a kernel minimum
increase; RHEL's BTF and backports remain required, and other missing required attachments still refuse the run.
Before loading or adopting selected syscall-result hooks, their tracefs return field must be eight bytes at
offset 16, matching the supported BPF wrapper. Divergent, missing, malformed or unreadable formats refuse the
hooks with a plain reason. Doctor and run tier selection withhold root tiers for any such layout refusal,
including listener capability rows; a present exec event cannot take the optional attachment fallback for this
failure. No enforcement is silently dropped.
The proof covers the ten affected suites on the matrix kernels and boots recorded in ADR 0024, not every RHEL 9
update, live distro LSM policy or the unrelated matrix failures.
RHEL's proc-directory oracle regression uses root's private `/proc/1/fd`: that kernel permits `/proc/1/fdinfo`
listings, so it cannot exercise the newer fdinfo directory permission hook. The fixture probes visibility as
the caller and logs this DAC coverage; kernels that deny fdinfo listings retain the permission-hook case. All
three inaccessible-name execs must still return EACCES without an `exec_missing` count. This is a test-coverage
distinction, with no product permission relaxed.

## C. Design gaps still open

| # | Gap | Do |
|---|-----|----|
| C1 | Step and thread derivation by content is heuristic: context compaction, prompt-cache edits or a changed system prompt start a new thread; tool ids are Anthropic-shaped. | Carry a confidence and a candidate set on every attribution; an `unattributed` bucket; provider-specific correlators. **→** **Closed**: E55 attribution confidence/method, record README. |
| C2 | Background threads (autosave, telemetry) get attributed to whatever step is open. | Attribute by tid where the thread never made a model call; otherwise `unattributed`. **→** **Closed**: E55 tid rule and `unattributed`. |
| C3 | Read aggregation could hide a single read of a secret. | Watch-list reads (deny_read and an explicit `watch` list) are always individual events; aggregation applies only outside them. **→** **Closed**: E56 `fs.watch`; SEMANTICS §7. |
| C4 | Net `ask` on raw TCP fights client connect timeouts (httpx 5 s). | For HTTP through the forwarder, hold the request instead of the connect (works for minutes). For raw TCP, document that ask is effectively "deny after timeout" unless the client tolerates it. **→** **Closed**: E51 `ask.hold` modes with the clients' real ceilings (600 s / 300 s), retries attached to the pending ask, 4-minute default for `request`. |
| C5 | Two rule systems (lists plus gate scores) with a precedence that users must learn. | Precedence in S6; `compile` prints the effective decision per declared entry; lint contradictions. **→** **Closed**: ADR 0007 gate only escalates; SEMANTICS §3; compile prints effective decisions. |
| C6 | The contract keeps growing (fs, net, exec, env, limits, gate, mcp, record, skills, prompt, visibility) and could become a rule language of its own. | Learn mode writes it; defaults cover the common case; the schema is versioned so fields can be deprecated. **→** **Closed**: E65 `extends` profiles + learn mode; versioned schema. |
