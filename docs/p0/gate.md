# Bounded scored gate

The implemented contract is [agent-contract R22a](agent-contract.md#5-business-rules), [SEMANTICS §3](../../spec/policy/SEMANTICS.md) and [ADR 0007](../adr/0007-gate-only-escalates.md). A gate runs after the ordinary tier decision and can only preserve or raise that floor. Kernel decision-core/plane parity remains separate; `compile --test` applies a hypothetical post-floor gate and never supplies a human answer.

```yaml
gate:
  rules:
    - fs.write outside worktree: 40
    - fs.read matches "*.env": 90
    - exec matches "rm -rf": 95
    - net to undeclared host: 70
    - net to api.example.com:443: 90
  thresholds: {allow: 50, ask: 80}
```

`rules` is a closed list of at most 256 single-predicate mappings. Scores and thresholds are decimal integers 0..100. The scores of the rules an action matches sum, saturating at 100 (the sum, not the highest rule). The bands: a score below `allow` allows, `allow` to `ask` (both inclusive) asks, above `ask` is refused; with the defaults, below 50 allow, 50 to 80 ask, above 80 refused. Thresholds require `1 ≤allow <ask ≤100`, so an unmatched action (score 0) always allows. *Amended 2026-10-20 ([ADR 0007](../adr/0007-gate-only-escalates.md) implementation note):* the two sentences before were "the inclusive ranges are allow ≤50, ask ≤80, then refused" and "Thresholds require `0 ≤allow <ask ≤100`"; a score of exactly `allow` was allowed, and the sum was not marked as a departure. Unknown fields/predicates, duplicate fields, null values, expressions, recursive `**` and malformed globs are rejected. Ordinary literal/glob arguments are at most 4096 bytes. The worktree is the captured compile/run working directory; relative read patterns use it and `~/` expands during compile. *Amended 2026-10-20 ([ADR 0007](../adr/0007-gate-only-escalates.md)'s fourth 2026-10-20 note):* an `fs.read matches` pattern with no `/` outside a character class matches a file's base name; one with such a `/` is a path pattern, a sequence of component globs each matching one name, matched against the clean path (an absolute pattern) or the clean path from the worktree (a relative one), one component at a time with `filepath.Match`; the root `/` has one empty name, which `/` and `/*` match, as `filepath.Match` matches it. A glob is malformed when any part of it is (`a*[` was accepted, read `exec matches` too). Compile refuses a read pattern no clean path matches, naming its clean spelling where it has one: an empty component (`secrets//*`, a trailing `/`), a `.` component (`./secrets/*`: `write "secrets/*"`), a `..` after a name or in an absolute pattern, a glob or class matching no name; and in a path pattern an escaped `/` and a class that can match `/` (`x/[^y]z`; write `x/[^y/]z`), which `filepath.Match` would match across a separator. A relative pattern may start with `..` components, for files outside the worktree; *amended 2026-10-24:* compile refuses one whose leading components must match `..` more times than the captured worktree has names, since no path from that worktree starts with more `..` and the rule would never fire in the run, naming the absolute pattern the agent's path resolves to when those components are each `..` (worktree `/home/u`: `../../../secrets/*` is `write "/secrets/*"`). Before, a pattern no clean path matches was accepted and never fired: under `fs.read matches "./work/secrets/*"` a read of `work/secrets/key` was allowed with no warning. *Amended 2026-10-24:* an escaped `/` and a class that can match `/` are refused for another reason: they did fire, since `filepath.Match` on the whole path matches each across a separator (`a\/x` matched `a/x`, `x/[^y]z` matched `x/az`), and the component reading would read them otherwise, so refusing them is a compatibility break; the refusal says so and names the spelling to write (`write "a/x"`). A pattern whose only `/` is inside a class (`a[/]b`) is a base-name pattern, which no name matches, and is refused as such. A `/` inside a class makes no path pattern: `"[^/]*.env"` matches a base name anywhere, where it matched the worktree's top level only.

## 5. Algorithms / rules

**R1 — Floors and bounded scores.** Ordinary refused floors keep their rule, reason and authority. A complete copied action can preserve or raise an allowed floor using the closed predicate program and the integer threshold bands described above (*amended 2026-10-20*, ADR 0007: "inclusive integer thresholds" before, under which a score of exactly `allow` was allowed). Missing relevant facts refuse as unreadable; a score never grants a floor-denied operation. *Amended 2026-10-05 ([ADR 0041](../adr/0041-race-free-supervisor-decisions.md) Step 1):* the supervisor's own walk of an end is one of those facts. A walk that failed with an errno the task's own lookup would not fail with (this process's EMFILE, ENFILE, ENOMEM or EIO; EXDEV from a procfs it cannot translate), or that reached a linked file whose path this process cannot see, leaves only the lexical spelling, which is not where the kernel lands: the action refuses as `gate.unreadable` rather than score the spelling, and an open whose walk failed so is gated rather than left observed. A walk that reached a nameless object (a pipe, a socket, an anonymous inode, an unlinked file) is complete facts, since no name can match it, and a lookup failure fails the task's syscall the same way. *Amended 2026-10-05 (ADR 0041 Step 4):* `fs.read matches` is a name predicate, so the end of a rename or hard link that leaves its name (the source, and the destination too under `RENAME_EXCHANGE`) is scored with the read predicates as well as the write ones, the stronger verdict kept. Before, `link("secrets/.env", "notes.txt")` or the same rename was scored with `fs.write` predicates only, and with none it was continued, so a later read of `notes.txt` read the secret under a name the gate scores 0 (`TestGateReadMatchesScoresRenameAndLinkSource`). A destination that only receives a name reads nothing, so `rename(tmp, x.env)` is not a read. A name made before the run, or by a mutation the gate does not see, remains the name-not-inode residual of ADR 0041 D1. *Amended 2026-10-16 (ADR 0041 Step 2 and Step 5):* for the same reason, an open whose access mode is not `O_WRONLY` reads the file it opens, whatever write bit it also carries, so an `O_RDWR` open, and an `O_RDONLY` one with `O_CREAT` or `O_TRUNC`, is scored with the read predicates as well as the write ones, the stronger verdict kept: by `gateOpen` and `gateFS`, by the held-open paths (a gate-raised ask's re-evaluation of the held inode, an `fs.ask` hold), and by R5's fail-closed answer for a handler that cannot finish (`decide.OpenReads`). Before, any open with a write bit was scored as a write only and, under a gate with no `fs.write` predicate, continued unscored, so under `fs.read matches "*.env"` alone `exec 3<>work/a.env; cat <&3` read the secret whose read-only open was refused, every time and with no race (`TestGateReadScoresAnOpenThatReads`, `TestGateReadScoresAHeldOpenThatReads`, and `TestGateReadRefusesAReadWriteOpen` on a real kernel and filter). An `O_WRONLY` open reads nothing and stays a write, and so does a mknod, which is recorded as an `O_CREAT|O_EXCL` open whose access mode reads `O_RDONLY` but opens and reads nothing (*amended 2026-10-16:* a read gate refused `mkfifo fifo.env`; `TestGateReadLeavesAMknodToTheWritePredicates`). R5's fail-closed answer for a handler that cannot finish refuses the source of a rename or hard link under a read gate alone too, which the read predicates score. `compile --test` keeps one direction per row: an `fs.read` row is a read-only open and an `fs.write` row a write-only one (the conformance actor's), so a run's answer for an open that does both is the stronger of the two rows' answers for its path, and a table states such an open as both rows. Its `fs.rename` row's source is scored with the read predicates too, as a run's is (Step 4); before, `compile --test` answered `allow` for the rename of a secret out of its name that a run refused `fs-gate`. *Amended 2026-10-16:* with a write gate too, `gateFS` had scored any open with a write flag as `fs.write` alone, so under `fs.read matches "*.pem": 90` an `O_RDWR` open of `out/x.pem` beneath a write entry read the file the same `O_RDONLY` open was refused, under a line with no gate fields. One scoring of an open (`scoreOpen`: the write predicates for a write open, the read ones for a read open and for a write open that reads, the stronger kept) serves `gateOpen`'s held inode, a held `fs.ask` write's target and an alternate (ADR 0057 D1), so each is scored as the agent's own open of that file would be (`TestGateReadMatchesScoresAReadingWriteOpen`, `TestGateReadAskHoldsAReadingWriteOpen`, `TestReadingHeldWriteIsPutToTheReadGate`, `TestGateFilesystemFaultScope`). *Amended 2026-10-17 ([ADR 0041](../adr/0041-race-free-supervisor-decisions.md) Stage B):* of the nameless objects above, a regular file with no link left on a filesystem with names, reached through a descriptor (`/proc/self/fd/N`, `/dev/fd/N`), lost a name an `fs.read matches` predicate may have matched: an open that reads it (an `O_RDWR` one included) has no complete facts for the read predicates and refuses as `gate.unreadable`, under both completions, whatever verdict the spelling's floor gave when this loop does not enforce that verdict (an advisory refusal is continued, and the kernel may allow the open). A read gate scores neither a write-only open nor an unlink, so a file the gate refused by name was read with no race: open it write-only, remove its name, reopen the descriptor for reading; its line read `allow unmatched` on the descriptor's procfs spelling. A write-only reopen keeps its facts (a write gate scored the unlink), and a file that never had a name keeps them too: one on the kernel's internal shmem mount (a memfd, a System V segment, a shared anonymous mapping). The cost: under a read gate an `O_TMPFILE` file the agent made cannot be reopened for reading through `/proc/self/fd` (its own descriptor still reads it), and neither can a file the agent unlinked (`TestGateReadRefusesAReopenOfAnUnlinkedFile`, `TestHeldPinWhoseNameIsRemovedIsUnreadable`). *Amended 2026-10-20 ([ADR 0007](../adr/0007-gate-only-escalates.md) implementation note):* a score of exactly `allow` asks (it was allowed); `allow: 0` is refused at compile (it would ask every unmatched action); `MayAsk`/`MayEscalate` count from `allow`; and the sum is kept (`TestGateThresholdBoundaries`, `TestGateScoresSumNotHighest`, `TestCompileTestGateBoundariesAndSum`). *Amended 2026-10-20 (ADR 0007's second 2026-10-20 note):* where the amendments above score an end or an open "with the read predicates as well as the write ones, the stronger verdict kept", both kinds now score it as one action, every matching rule of either kind once and their scores summed (`gate.Action.Reads`; `scoreOpen` and `gateFS`): under `fs.read matches "*.env": 30` and `fs.write outside worktree: 30`, an `O_RDWR` open or a rename of `out/prod.env` scores 60 and asks (a rename is refused, no approval completes it) where it scored 30 and was allowed. The two ends of a rename or hard link stayed two actions, the stronger kept, so a write rule matching both was not counted twice (*amended the same day, ADR 0007's third 2026-10-20 note:* a rename or hard link is one call, one line and one verdict, so it is one action over both its ends (`gate.Action.Dest`): every rule that matches an end it scores counts once and the scores sum, the write predicates scoring both ends and the read ones the source and, under `RENAME_EXCHANGE`, the destination. A write rule matching both ends still counts once and the score is never below the stronger end's; it differs only where different rules match different ends: renaming `work/prod.env` to `out/x` under the pair above scores 60 and is refused where the stronger end scored 30 and it was allowed. A read of the source and a write of the destination made as two calls are still two actions, each scored alone; `TestGateMoveCountsEachRuleOnceAcrossItsEnds`). Held completion, the broker requirement and the (D) cells use the subset-sum over both kinds' rules (`MayEscalateReadWrite`, `MayAskReadWrite`). `compile --test`'s `fs.rename` row sums its source's kinds as a run does; an open that both reads and writes is still no row, and its score is at least each of the two rows' scores for its path (`TestGateReadingWriteSumsBothKinds`, `TestGateSumsReadAndWriteKindsOfOneEnd`, `TestCompileTestGateSumsReadAndWriteOfAMoveSource`). *Amended 2026-10-20 ([ADR 0041](../adr/0041-race-free-supervisor-decisions.md)'s note of the same day):* a move renames every file beneath the directory it moves, so the end of a move that leaves its name is scored as the directory it may be too: an `fs.read matches` pattern holding a `/` also matches that end when it can match a path beneath it (an ancestor of the pattern's directory included) and, for a relative pattern, when the end is the worktree or holds it. Before, the end was matched by its own name alone: under `fs.read matches "work/secrets/*": 90`, `mv work/secrets work/public` was continued at score 0 and `cat work/public/key` read the secret `cat work/secrets/key` was refused, with no race. The gate has no file type, so the move of a regular file named as the pattern's directory is scored too; a name-only pattern scores no directory's move, the base names beneath it unchanged (`TestGateReadMatchesScoresAMovedAncestor`, `TestCompileTestGateScoresAMovedDirectoryOfAReadPattern`). *Amended 2026-10-20 (ADR 0007's fourth 2026-10-20 note):* "can match a path beneath it" was answered by an automaton that stepped a rune at a time where `filepath.Match`'s star skips bytes, so under `fs.read matches "work/*[가-�]/key"` the move `mv work/é work/x` was continued at score 0 and a read of `work/x/key` read the secret. A path pattern is now component globs (the grammar paragraph above), and an end lies above a match when it has fewer components than the pattern and each matches its glob by `filepath.Match` itself, the function that matches a path (`TestGateMovedDirectoryWithAMultibyteName`, `TestReadPatternAgreesWithFilepathMatch`). *Amended 2026-10-20 ([ADR 0041](../adr/0041-race-free-supervisor-decisions.md)'s note of the same day):* "the gate has no file type" no longer holds. Under a wildcard directory component every end at that depth was taken to be the pattern's directory, so under `fs.read matches "*/.env"` every move of a regular file there, an editor's atomic save `rename(.out.json.tmp, out.json)` included, was refused. When a read rule is a path pattern, the decision stats each end that leaves its name (not followed); an end found to be no directory, or missing, has nothing beneath it and is matched by its own name, and one whose stat fails otherwise is taken to be a directory. A directory reaches a checked name only through its own move, which is scored where it stands. `compile --test` reads a move row's object as a directory when it exists as one or the row says `dir: true` (`TestGateMoveOfANonDirectoryIsMatchedByItsName`, `TestGateReadMatchesScoresRenameAndLinkSource`, `TestCompileTestGateScoresAMovedDirectoryOfAReadPattern`).

**R2 — Copied exec facts.** Exec matching conservatively checks each rule once against three available copied command spellings: requested pathname basename, resolved image basename, and argv[0] basename, each followed by copied argv[1:]. A caller-supplied argv[0] can add an escalation but cannot erase a match on the other names. A copied vector exceeding 128 arguments or its 4096-byte budget is unreadable and refused. These facts describe a notification-time snapshot, including multicall aliases; they do not certify later kernel argv or program behavior. A pattern's first word is therefore a bare name: `gate.New` refuses one holding a `/` (`/usr/bin/curl *`, `*/curl *`, `./tool`) and names the basename to write; a `/` after the first word is argument text (*amended 2026-10-05:* such a pattern was accepted, printed as an active rule, and never matched an executable). *Amended 2026-10-06 ([ADR 0048](../adr/0048-exec-command-rules.md) (5)):* `exec matches "<p>"` also matches when `p`, read as a command pattern with the shared matcher (`pkg/policy/execmatch`, docs/spec/exec-command-rows.md), matches under deny semantics; the rule matches the union of both readings, so no rule matches less than before. `exec matches "rm -rf": 95` now also scores `rm -fr`, `rm --recursive --force` and `busybox rm -rf`, and `git push` scores `git -C . push` and git's autocorrected `git psuh`. A pattern whose command word holds a glob keeps the glob reading alone. The gate reads names and argv only (no file identity, no `#!` form). `compile` prints each rule's command reading under the gate table (`TestExecMatchesReadsCommandPatterns`, `TestCompileListsBroadenedGateRules`). *Amended 2026-10-16 (ADR 0048 (5)):* a command reading that overflowed (a dispatch past the matcher's depth bound, such as `busybox` nested seven deep, or more readings than its count; the `ViaOverflow` sentinel) matches every command-pattern rule, each at its own weight, since a reading that was dropped may reach any of their tools; it matched none, so `busybox busybox busybox busybox busybox busybox busybox rm -rf x` escaped `exec matches "rm -rf"` (`TestExecMatchesFailsClosedOnOverflow`).

**R3 — Bound destination facts.** A hostname `net to host:port` requires that exact host/port in declared `net.allow`, `net.ask` or `models`. Literal IP predicates can score other destinations without DNS resolution. Scoring considers all current bounded aliases of the copied destination IP, protocol and port, including mapped IPv4 and, *amended 2026-11-01*, an IPv6 scope id, which names a link and no other destination (a rule cannot carry one, and `[::1%1]:P` reached what `net to [::1]:P` names with no score). Expired aliases and opposite-protocol declarations contribute nothing; more than 256 distinct aliases refuses as unreadable. Runtime resolver, capture-loopback and DNS-broker grants supply ordinary floors but are not user-declared destination facts: `net to undeclared host` can escalate them. Dynamic broker/proxy endpoints cannot always be declared in advance; choose scores and predicates deliberately when combining gates with those cooperating helpers. Direct declared model destinations remain declared. An IP/alias does not prove a remote TLS/HTTP service identity. The separate [network controls](network-controls.md) and [proxy protocol contract](proxy-protocols.md) govern those boundaries. *Amended 2026-10-05:* `compile --test` reads a table row's destination as `Evaluate` does — no `proto:` is TCP, a `path:` with no host a unix socket — before collecting aliases; it matched the row's raw proto, so a row by address with no `proto:` skipped every `tcp://` entry's alias (every `net.ask` entry is one) and answered `allow` where the run refuses `net-gate`, and a unix row answered a gate ask `ask` where the run refuses it as unsupported. *Amended 2026-11-01:* a rule that names this host is on the destination, not on a spelling of it, as a live block is: a rule on a loopback or unspecified literal, a name under `localhost`, or one of the host's own addresses scores whatever reaches this host on its port, read by `pkg/policy/thishost`: every loopback address of either family, the unspecified addresses (refused unread as before), the host's own addresses, and a datagram to a multicast group, `255.255.255.255` or a subnet's broadcast address. Compared as written, a rule on `127.0.0.1:P` scored nothing for `127.0.0.2:P`, `[::1]:P` or the LAN address, each of which reaches a server on all interfaces, and a rule on `[::1]:Q` nothing for `127.0.0.1:Q`, under a `net:` section's CIDR entries as well as with none. It costs at most another local server on the rule's port, or a group send on it. A rule on a group or a broadcast address names no host and matches that address alone. A hostname rule that is not a loopback name is matched by the addresses the name resolves to, as above, so one that resolved to `127.0.0.1` does not reach `127.0.0.2`. The host's own addresses and subnet broadcasts come from the supervisor's snapshot, so a `compile --test` row, which has none, answers them as any other address: a row by this host's LAN address under a rule on `127.0.0.1:P` reads `allow`, and the run refuses it, and a rule on a LAN literal scores a loopback row nothing. While the snapshot cannot be read at all, a destination on the port of a rule on an address literal is refused, since either may be this host, as under a live block. GAPS C46 lists what the reading leaves out.

**R4 — Safe completion.** The supported held completions retain the original object, credentials and protected checks; unsupported combinations refuse explicitly.

| Result after the ordinary floor | Completion |
| --- | --- |
| Refused floor | Original rule, reason and authority retained; no gate relaxation |
| Allow score | Ordinary operation path; score metadata retained when recorded |
| Ask: regular-file read/write open | Pin original inode or absent create parent, retain original credentials/umask and protected checks, then approved `ADDFD\|SEND` descriptor delivery |
| Ask: ordinary TCP connect | Authenticated broker plus exact duplicated OFD/address; root tiers require one-shot socket-cookie credit |
| Ask: TCP first write | Bounded private relay; no upstream connect or delivery before the approved first received bytes |
| Ask: exec, UDP/Unix/raw, Fast Open, non-open FS mutation | Explicit unsupported-completion refusal; no approved CONTINUE |

Separate `fs.ask` scopes remain write-open/create only. Gate request-mode destination approvals are rejected; cooperating HTTP request holds remain the separate [agent-contract R22 ask contract](agent-contract.md#5-business-rules). Observe, setuid and io_uring modes cannot use this gate.

*Amended 2026-10-16 ([ADR 0041](../adr/0041-race-free-supervisor-decisions.md) Stage B):* `gate.completion: held` (default `copied`) makes "Allow score → ordinary operation path" race-free for opens: every open of an fs kind whose rules can score to `allow` or above (*amended 2026-10-20*, ADR 0007) is held, never continued. The run's open deputy, a process of the run (its Landlock domain, cgroup and credentials, started by the child stage before the listener filter), pins what the task's lookup reaches; the supervisor refuses on the copied name first, then decides on the pinned object (D4's classes: a block device or a character device other than the memory and tty classes refused `held-unsupported`; the floor checks; the larger of the copied and pinned scores); the deputy opens it with the task's flags and umask, so Landlock, the decision plane, fanotify and DAC decide that open as they decide the agent's and the descriptor carries the domain's `TRUNCATE` and `IOCTL_DEV` rights; and the descriptor, verified to be the pinned inode, is delivered with `ADDFD|SEND`. A lookup failure or a fault answers the task's own errno; a deputy that cannot answer, or a held-open ceiling reached, refuses (`held-unavailable`, `held-limit`), never continues. The floor on the pinned object is the copied path's own (the contract's verdict for the tier, supervisor R15c's `deny_write` targets for a write), so the key changes how an open is completed and never which opens a tier allows; an errno the deputy's open meets in the kernel is the task's answer and the line's `syscall_ret`: an `EACCES` or `EPERM` the tier's model explains is that mechanism's refusal under the model's rule, and any other keeps the floor's verdict (an `EACCES` from the file's own permission bits names no contract refusal). The ask range on the pinned object takes the stricter checks a hold always took (the nearest `deny_read`, the targets no approval reaches), then a person's answer, then the deputy's open; a person may answer with an alternate (ADR 0057), reopened as the task's credentials and delivered in the target's place as on any hold. Two cells stay copied: an `O_PATH` open (`ADDFD` cannot carry one; it reads nothing, and an open of contents through it is held), disclosed `gate.fs.read/o_path`, and the non-open mutations. The key is an opt-in because Stage B's budget was missed (ADR 0041 §Performance, TARGET-MISS 2.01× the gated path's p50). `TestGateFSOpenRaceIsHeldAndRaceFree` races a read-open's name between `*.env` and a file, a directory, /dev/null and a missing name: 390 of 3,200 reached the secret with the copied cell, none held; `TestHeldOpenDifferential` holds 49 open shapes to the kernel's own answers (35 before that day, whose trailing-slash cases had lost their slash; `O_CREAT` on what exists and flags the kernel refuses before the pathname now answer as the kernel does, and a symlink to the gated file and an append through a symlink to a `deny_write` target are refused on the pinned object); `TestIntegrationHeldOpenNeverExceedsLandlock` approves a create under a write entry's name after its parent moved away, which the copied completion made on a supervisor thread outside the run's domain and the deputy is refused by the run's Landlock rule; and the conformance suite's `fs-held`, `link-held` and `denywrite-held` fixtures run the `fs`, `link` and `denywrite` cells with every open held, on every axis, to the same answers. Not built, a residual (ADR 0041): D2's LSM label check. A held open is made under the deputy's own LSM label, so a process of the run that an AppArmor profile or a SELinux domain confines more tightly than the deputy (an agent binary with a profile of its own, or a tool it execs into one) is not held to that confinement for its held opens; a run that starts its deputy on a host with AppArmor, SELinux or Smack active warns so once.

Enabled action kinds retain seccomp notifications under summary/off, the chmod family included, which an `fs.write` gate scores as a write, and, under an `fs.write` gate, the xattr and chown families, which it scores as writes too (*amended 2026-10-16, ADR 0041 Step 2:* a POSIX ACL is the extended attribute `system.posix_acl_access`, and setting one rewrites the mode bits, so a gate that refused `chmod 755 ../outside/f` let `setfacl -m u::rwx,g::r-x,o::r-x ../outside/f` make the same change with no score and no line; every attribute name is scored, the name never read, since a sibling thread can rewrite the copy; timestamps, `utimensat` and its older forms, are not notified and not scored: they change no permission, and `tar x` sets one per file; `TestWriteGateNotifiesXattrAndChown`) (amended 2026-10-05: the filter notified the chmod family under `record: full` only; *measured 2026-10-16, [ADR 0041](../adr/0041-race-free-supervisor-decisions.md) Step 2:* each notified mode change costs one supervisor round trip, about 51 µs at a box load of 7–9 and 84 µs at 15–20: GNU tar's `xpf` of 10,000 files whose modes carry a setuid bit, 10,101 mode changes, took a median 1,805 ms under tier 1 with `fs.write outside worktree: 90` against 1,193 ms without it, and a plain `tar xf`, which changes no mode, 46 ms more, within noise; `TestWriteGateNotifiesChmod` refuses a gated `fchmodat` and `fchmod` end to end at `summary` and `off`); FS gates disable the plane-filter shortcut and exec gates bypass the fast handover until scored. Addressed/unaddressed IP datagram batches return ENOSYS under a network gate. *Amended 2026-10-05:* a run whose gate scores `net` actions therefore launches with `single-request` appended to `RES_OPTIONS`, as a `models[]`-guarded launch does, whatever its capture mode, so glibc's paired A/AAAA lookup is two individual sends rather than the `sendmmsg` batch glibc does not retry after ENOSYS; an agent that clears its environment, or batches its own datagrams, still gets ENOSYS. Supported individual UDP sendto/sendmsg paths use bounded copied-address/payload relays. *Amended 2026-10-05:* that relay is for IP sockets only; an addressed Unix datagram the gate scores Allow is continued as [supervisor R13b](supervisor.md)'s best effort, so the agent sends it from its own cwd, Landlock domain and credentials, and tego never sends it for the agent. Ordinary static/kernel refusals still have priority. The gate does not revoke existing/imported descriptors or claim complete packet filtering.

*Amended 2026-10-05 ([ADR 0041](../adr/0041-race-free-supervisor-decisions.md) D6, Step 3):* the table's "Allow score → ordinary operation path" no longer means `CONTINUE` for a network action on an IP socket. Under a contract with no `net:` section a gate-allowed connect or Fast-Open send was continued, the kernel read the address again, and a sibling thread that rewrote it after the gate scored the copy reached a destination the gate refuses (about one attempt in five on the test machine; the ledger named the benign one). Now, whenever the gate scores `net` actions, a connect, Fast-Open send or addressed datagram the gate admits on a socket whose own `SO_DOMAIN` is `AF_INET` or `AF_INET6` (or cannot be read) is performed by the supervisor on the duplicate with the copied bytes the gate scored, whatever family they spell: a unix-spelled copy on an IP socket gets the kernel's own `EAFNOSUPPORT` from the relayed call. The domain is the socket's, never the copied family word, which a sibling can flip. A relayed socket carrying a source route (`IP_OPTIONS` LSRR/SSRR, `IPV6_RTHDR`), or whose options cannot be read, is refused, rule `relay-source-routed`: its first hop is not the scored address. Unparsed families and `AF_UNSPEC` keep refusing as `gate.unreadable`. On a unix-domain socket no sibling can reach an IP destination; with no `net:` section its connects and datagrams stay best effort. Blast radius: the run's whole IP egress then takes the relay path (+12–32 µs per connect or send, a ceiling of Workers+64 outstanding relays beyond which a connect is `relay-limit`); ancillary data, `UDP_SEGMENT`, `MSG_ZEROCOPY` and datagrams the relay cannot send whole are refused, as on any relayed socket; a host MAC LSM mediates the relayed call under tego's label; tier 2/3 per-run `connect4/6` programs still decide on the socket's cgroup, which the duplicate keeps. *Amended 2026-10-05 (ADR 0041 D6; [enforce-landlock](enforce-landlock.md) R11b):* the `relay-source-routed` refusal above reads the socket's options before the relayed call, and that read alone is a snapshot a sibling can race: `setsockopt` was not trapped, so a sibling could add an LSRR/SSRR option or an IPv6 routing header between the read and the relay, and the first hop went to an address the gate never scored.
