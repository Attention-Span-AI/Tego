# ADR 0017: the kernel is the judge: a generated conformance suite checks the record, compile --test and contract invariants against real syscalls

Status: accepted 2026-09-28; handwritten v1 cells and subsequent static-table, plane-mode and CI integration are implemented, and so are the baseline's per-kernel conditions, canonical form and `-conformance.update=<space>`, and the oracle's completion: nearest wins for mutations, no silently dropped plane axis, the effect judge, the capability cross-check, the per-axis report and budget, and tier 1 without root (2026-10-05, the notes at the end). Every handwritten cell is a table in spec/policy/conformance (schema v2), and deterministic generation is built with space 1 (the fs grid), its manifest and the mutated-contract self-tests (2026-10-19); actor spaces 2, 4, 5 and 6 are built, with the process and control cells and no deferred cell left (2026-10-19); space 3 beyond its capture-listener and send cells, and space 7, remain open. Every enforcement change in this set lands behind the supported conformance suite.

Implemented as v1 (2026-09-28): a table of hand-written cells, not yet generated. test/conformance holds 5 fixtures (fs, link, denywrite, exec, net) and 54 cells, each a contract fragment, one action and its expected verdict and rule per tier. The unprivileged runner (`go test ./test/conformance`, no tag) checks every cell against `tego compile --test` per tier (ADR 0019), through a binary built with tegotesthooks so it touches nothing under the invoking user's ~/.tego. The root runner (TestConformanceKernel, tag integration, in test/integration-skips.txt and test/vm/root-must-pass.txt and run by test/vm/root-suites.sh in the KVM guest) performs each fixture's actions in one real `tego run` at tier landlock and at tier cgroup through a static helper (test/conformance/cmd/actor) and checks the kernel's own result, the ledger line and the invariants of (c) for the fs, exec and net kinds against the cell. The mode axis exists in the table (the key of a cell's expectation is tier and mode: lsm, fmod_ret, fanotify) and v1 fills only fanotify at tier cgroup; tier bpflsm holds three compile-only expectations until a build contains it. Baseline: 58 entries in testdata/baseline.json (11 compile --test, 47 ledger, 0 kernel), each with its reason; the ratchet fails on a new failure and on an entry that now passes. A cell where the kernel allows what an invariant refuses is a Cell.Finding: reported by the root runner, never baselined, and failing once fixed so the note goes with the fix. One is open (exec/read-file-inside-exec-entry-directory-inside-deny-read at tier landlock: an exec.allow directory inside a deny_read grants READ_FILE beneath it). Not built in v1: the generator (gen.go), -update, the exec spellings loader and memfd, the capture-listener cell, the TOCTOU harness, bind mounts and overlayfs, the third-party fanotify listener (test/conformance/cells.go, Deferred), and the CI jobs (conformance-tier1, conformance-guest, the nightly step).

Decision: test/conformance is a Go suite under the integration build tag, with no model inside it (ADR 0003). It generates contracts over the entry kinds {none, write, deny_read, watch, deny_write target, exec entry} at several depths and runs real actions under a real tego run per tier and per decision-plane mode: read, write-open, create, truncate, delete, rename within and across entries, mkdir, rmdir, symlink, hard link, chmod, exec (by name, symlink, hard link, script, the loader directly, memfd), connect and send (allowed and refused), socket and socketpair families. All actions of one contract run in one tego run. For every action it records the kernel's own result (the judge) and checks against it:
(a) the ledger: verdict, rule, and at most one verdict line per action;
(b) compile --test for that tier and mode (ADR 0019);
(c) invariants derived from the generated contract alone, never from the Landlock plan or the decision core: no write, create, delete, rename or mkdir succeeds outside write entries; no read succeeds under a deny_read the capability line reports enforced at that tier; no exec of a file outside exec.allow succeeds when exec: is present; no connect or send to an undeclared destination succeeds under a net: section; no socket outside ADR 0018's allowlist is created; no mutation of a deny_write target or of a directory between its write entry and the target succeeds where the capability line reports deny_write enforced; at tiers 2 and 3 with a plane mode, a refused create leaves no file.
*Amended 2026-10-05:* the read invariant follows SEMANTICS §2's nearest wins: a read under an enforced deny_read is a fail-open only when no write entry nested inside that deny_read, and so nearer to the path, covers it; a deny_read nested inside such a write entry is held to the invariant on its own. Without that the oracle called filesystem.yaml's regranted-read cell a fail-open at every root tier (TestInvariantReadIsDecidedByTheNearestEntry).
A checked-in baseline of known-failing cells (test/conformance/testdata/baseline.json, each with a reason) ratchets: CI fails on a new failing cell and on a baseline cell that now passes until the baseline drops it. A cell where the kernel allowed what an invariant refuses is a fail-open: it never enters the baseline, -update refuses to add it, and the PR that exposes one fixes it or does not land. New cells enter the baseline only in the PR that adds their space. Tier 1 runs on the hosted runner; tier cgroup runs per PR in one GUEST (6.17, with bpf.plane: fmod_ret once ADR 0024 lands) when a change touches bpf/, internal/runtime/enforce, internal/runtime/supervisor, internal/runtime/observe or internal/policy; tiers 2 and 3 run nightly on every MATRIX row in every mode the row can select. After ADR 0028 the cases move to spec/policy/conformance/*.yaml (the compile --test format extended with per-tier outcomes and side effects), which makes SEMANTICS §2, §4 and §5 executable.

Why: [measured] The prototype (oracle.py and analyze.py, scratch scripts that are not kept in the repository) runs the 64x12 fs grid in 4.4 s at tier 1 and about 70 s at tier cgroup (64 runs of about 1.1 s). It found every mismatch ADR 0016 fixes, Evaluate wrong on 12 of 768 (tier 1) and 28 of 768 (tier 2), and 12 refused creates that left a file. Unit coverage of 77-98% missed all of them.
[inference] ADR 0016(2) makes the tier-1 model read the builder's own plan and ADR 0028 makes Evaluate, the tier-1 model and the plane's row compiler one function; an over-grant they share is invisible to a consistency oracle (kernel allows, ledger says allow, compile --test says allow). Only expectations derived from the contract itself catch it.
[measured] A run that cannot adopt a pinned build pays attach plus detach of 21-22 links with the plane (1.81 s + 1.81 s on 6.8 and RHEL 9; up to 3.7 s of removal on AL2023 6.1), so the budget only holds with ADR 0022's linger and one run per contract. [documented] .github/workflows/vm-matrix.yml runs nightly (cron), so a tier-2 regression could merge unseen.

Security argument: The invariants are the one check independent of the Landlock plan and of the decision core, so a fail-open that plan, ledger and compile --test share still fails CI, and fail-open cells can never be baselined. It is the characterization test every enforcement change in ADRs 0016, 0018, 0021, 0024-0028 and 0033 lands behind, and it adds nothing to the runtime.

Options considered: Chosen: independent invariants now; decision tables after ADR 0028.
Rejected:
- Model-to-model differential tests only: cannot see the Landlock builder or a model both components share.
- A consistency oracle without invariants: blind to a shared fail-open once ADR 0028 merges the models.
- Nightly-only guest runs: a tier-2 regression can merge.
- A model-based oracle: excluded by ADR 0003.

Consequence: Every fix in ADRs 0016, 0018, 0021 and 0024-0028 states which baseline cells it removes. The first baseline records today's disagreements as data, never a fail-open. CI time: seconds at tier 1; about 70 s per enforcement PR in the guest; 1-3 minutes per matrix row and mode nightly after ADR 0022.

Implementation plan:

Port oracle.py and analyze.py to test/conformance/{gen.go, run.go, judge.go, invariants.go, baseline.go}. The runner builds one contract per cell group and runs every action in one tego run through a small static helper, test/conformance/cmd/actor, that performs the actions and prints each syscall's result as JSON lines.
Space, one PR each: (1) today's fs grid with invariants and baseline; (2) exec spellings (C30/C31) and ADR 0032's AT_EXECVE_CHECK probe cell; (3) net and socket families (with ADR 0018); (4) deny_write ancestors and the TOCTOU harness (a racing thread swaps a symlink between the supervisor's read and the kernel's lookup); (5) symlinks, bind mounts, a loop-file btrfs with subvolumes and an overlayfs mount in the guest (ADR 0025); (6) a third-party fanotify listener refusing an open, on one row at 6.12 or below and on 6.17 (ADR 0016).
CI: conformance-tier1 on the hosted runner; conformance-guest, path-filtered, per PR, running the fs grid at tier cgroup in one GUEST where the runner exposes /dev/kvm (else a self-hosted runner); the nightly vm-matrix gains a conformance step per row and mode. Guests set bpf.linger in /etc/tego/config.yaml once ADR 0022 lands, so runs adopt the pinned build (136-204 ms a run, measured).
Budget, stated as runs per row: tier 1 under 10 s; tier cgroup before ADR 0022, the fs grid only (64 runs, about 70 s); after ADR 0022, at most 600 runs per row and mode, under 3 minutes.
Self-tests: a mutated build (fsVerdictIn forced to allow) fails an invariant; -update refuses a fail-open cell.
Docs: ADR 0017; test/conformance/README.md (reading a cell, baselining); spec/policy/conformance/README.md after ADR 0028 S6.

*Amended 2026-10-05 (the baseline's per-kernel conditions, canonical form and update):* the baseline stays the one reviewed file, test/conformance/testdata/baseline.json, and a v1 file is a valid file of the new form. An entry may carry a `where` object that names the machines it was written for: `kernel_min` and `kernel_max` (`uname -r`'s major.minor, inclusive, compared as numbers), `abi_min` and `abi_max` (the Landlock ABI), `arch` (GOARCH), `bpf_lsm` (bpf among the active LSMs) and `row` (the matrix row, `$TEGO_VM_ROW`). A field left out matches every machine. A run applies, and can find stale, only the entries whose `where` matches the machine it ran on, so a disagreement that exists on 6.1 alone is baselined once, for 6.1, and is neither excused nor reported stale on 6.17. One file with predicates rather than a file per row, because the reviewer then sees every excuse in one place and an entry that holds on every row is written once. The file is decoded strictly (a field it does not know is an error, since a misspelt `where` key dropped silently would widen an entry) and has one canonical encoding (sorted by key, then by `where`; two-space JSON; a final newline), which TestBaselineCanonical holds it to. `-conformance.update=<space>` rewrites the file from a run. It drops the entries the run could judge that now pass. It adds the run's new disagreements of the named space's cells with the reason `TODO` and the machine's `where` (none for compile --test, which makes no kernel call, ADR 0019); TestBaselineIsWellFormed refuses a `TODO` reason, so a baseline a tool wrote cannot be committed unexplained. It refuses, and writes nothing, when the run had a fail-open or any other error a baseline cannot excuse, when a new disagreement belongs to another space or to none or is reported under a runner no baseline can hold, when the space does not exist, and when `-run` or `-skip` narrowed the run below a whole runner. A space is a named set of cells in `Spaces()`; today it is `handwritten`, the cells of fixtures.go and the YAML table, and the generator and the later spaces register theirs. The self-test "-update refuses a fail-open cell" is TestUpdateRefusesFailOpen; the mutated-build self-test is not built.

*Amended 2026-10-05 (the oracle's nearest wins for mutations; no plane axis drops silently):* the nearest-wins rule of the read invariant (the note above) decides a mutation too. The oracle takes the deepest declared write or deny_read entry at or above each name an action modifies (a write-open, create, truncate, unlink, rmdir, mkdir or symlink's path; both ends of a rename; a hard link's source and new name), whatever order the contract lists them in, and a success there under a deny_read the tier enforces is a fail-open: a deny_read nested in a write entry refuses every modification beneath it at the root tiers (ADR 0021 (5), supervisor R15d; the plane by inode), and a write entry nested in it grants them again. chmod is not held to it (agent-contract E35). At tier landlock such a deny_read is unenforced, so nothing beneath it is held to it. TestInvariantNearestEntryDecidesEveryAction covers three levels, both declaration orders and a symlinked spelling. The root runner also stops dropping a plane axis: where bpf is an active LSM and doctor does not select the lsm mode under its pin, TestConformanceKernel fails, as it already did for tier bpflsm; `TEGO_CONFORMANCE_REQUIRE` accepts `bpflsm`; and test/vm/root-suites.sh sets that variable per boot (test/vm/conformance-require.sh): `cgroup,fmod_ret` on every root boot, plus `lsm,bpflsm` on a boot with bpf among its LSMs when the objects are built. It was `cgroup,fmod_ret` on both boots, so the lsm-bpf boot could lose both axes with nothing failing. The variable also accepts `landlock`, with which a tier landlock that doctor refuses fails the test rather than skipping it; RequireEnv's comment (test/conformance/baseline.go) names every value.

*Amended 2026-10-05 (the effect judge, the capability cross-check, the per-axis report and the budget):* (c)'s last invariant is built as an effect judge for every fs mutation, not for creates alone (test/conformance/effects.go). The kernel runner snapshots the project tree before and after each fixture's run; a refusal that left its effect (a new name after a refused create, mkdir, symlink or link; a missing name after a refused unlink, rmdir or rename; changed content or mode after a refused truncate or chmod) is a fail-open on every axis, never baselined, and a success the tree does not show fails as well. The stated residue of tier cgroup's fanotify listener (docs/p0/enforce-cgroup-observe.md: it answers an O_CREAT open after the inode exists, so a refused create leaves an empty file) is encoded in the judge rather than baselined: on that axis an empty regular file is logged, and a non-empty one is a fail-open. "Where the capability line reports" an entry enforced is now checked rather than assumed (test/conformance/capability.go): the oracle's enforcement predicates (deny_read: tier landlock unless a write entry covers it, the root tiers always; deny_write: only where a plane decides) are held to each run's run_start line (capabilities fs.deny_read, best_effort deny_write/default, and the decision_plane the axis pinned) and to `tego compile --json`'s per-entry markers; a disagreement is a "capability over-claim" or an "oracle stricter than product", fails the runner and is fixed on one side, and the deny_write invariant binds through that predicate instead of a hard-coded tier. Each axis' results are a report (runs, wall time, fail-opens, effects, problems, findings and the baselinable disagreements); the budget is enforced per axis (at most 600 runs and 180 s, 10 s for the landlock axis): a miss is printed TARGET-MISS with its number and fails under TEGO_CONFORMANCE_BUDGET=strict (which nothing in CI sets yet: root-suites.sh passes it through, a guest run sets it by hand, and the conformance CI's conformance-guest job and vm-matrix will set it), and TEGO_CONFORMANCE_REPORT=<file> appends one JSON line per cell and axis for a cross-row report.
