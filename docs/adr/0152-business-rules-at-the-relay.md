# ADR 0152: business rules at the relay

Status: accepted design, 2026-11-12. Implements the integration boundary of ADR 0151 against `6072cc1dde5597039b482008c33bc8ca33a5e162`. Acceptance of this design does not certify an implementation or a kernel profile. Proposed APIs below are implementation requirements until backed by tests. The specification and both pure evaluators remain unchanged.

## Context

The feature is a restriction on submitted calls on one admitted route. Ship the first useful guest path with a per-call cap, replay protection, durable admission and a real boundary. Add cumulative accounting, exact-call approval, installed-server qualification and authoring in separate releases. Do not activate an argument-rule switch against today's shim/server arrangement.

The frozen authority is [ADR 0151](0151-business-rules.md), [requirements](../../spec/policy/bizrule/v1/README.md), [wire](../../spec/policy/bizrule/v1/WIRE.md), [adapter](../../spec/policy/bizrule/v1/ADAPTER.md) and [integration acceptance](../../spec/policy/bizrule/v1/ACCEPTANCE.md). This record and the integration amendment to ADR 0151 do not change v1 predicates, canonical bytes or vectors. A separate approval protocol is required by W026 before asks can be enabled.

## Decision

### 1. Final admission in the relay

#### Call site and bytes

The call site is `(*stdioConn).decideCall`, immediately after the existing `res := c.s.decide(c.server, cl.tool)` and **before its existing `switch res.Decision`**, hence before emitCall, askPerson or ToServer. A business-bearing server takes a new `decideBusinessCall` branch there and returns; it cannot fall through to a second allow path. `Service.evaluateBusinessLocked` in proposed `internal/runtime/mcprelay/business.go` constructs the request and calls `bizrule.EvaluateBundle(bundle, request)` directly in this Go process. There is no Rust process, subprocess transport or fallback evaluator on the live path.

There must also be a guard at the **start of clientLine, before wireLine/readCalls and the existing non-call and batch shortcuts**. `clientBusinessLine(raw)` owns intake on these servers. It refuses a batch as a whole, routes only a closed list of protocol housekeeping messages, and sends every tools/call through strict intake and decideCall. HTTP business activation refuses at configuration/admission, and an accidental HTTP runtime entry refuses as well. Merely adding the call site without these guards is unsafe.

New additive Go API work is necessary: the current leaf has no intake canonicalizer or accessor for a validated replay-key digest when Reservation is nil. Add a bounded, token-preserving `PrepareCall`/opaque `PreparedCall` API in pkg/spec/bizrule, sharing the leaf's strict lexical parser and adapter validation. It may strip inter-token whitespace and sort objects only after checking complete grammar, depth/member/byte bounds, decoded duplicates, exact literal keys, integer tokens and string spellings. It must not repair exponent numbers, escapes, casing, surrogates or unknown fields. It exposes a copy of canonical content and, only after adapter validation, the safe key digest. No raw identifiers become public safe facts. EvaluateBundle still validates the frozen candidate independently through its existing v1 path. This is an API addition under W014/W024, not a new wire field or changed predicate.

Retain the raw input only in bounded volatile intake memory. Keep the validated canonical content immutable through evaluation, holds and the pipe write. Compute W003 call_digest from these content bytes, without transport LF. Forward these identical bytes plus one LF. Do not unmarshal into float64, extract by searching for an amount, reserialize through a struct with omitted fields, or rebuild the call after approval. A rejected candidate's digest covers the exact candidate bytes evaluated; an intake failure can record its input digest with explicit `not_evaluated` provenance, never pretend it was a canonical forwarded call.

The request is built from these authorities:

| W005 field | Source |
|---|---|
| version=1, adapter | Compiled, validated bundle and linked adapter support. |
| run_id | Runtime RunRef.ID, not a frame or environment variable from the agent. |
| request_id | Durable owner's increasing uint64 evaluation sequence; separate from JSON-RPC id and broker ask_id. Never reused; recovery retains its high water. |
| server | Admitted worker/session's configured server label, never params or a model claim. |
| call_hex | Exact immutable canonical content above, lower-case hex. |
| contract_bundle_digest | Compiled pin, independently checked against Bundle.Digest at launch. |
| contract_verdict, tool_source | Fresh effective mcptool result plus installed/profile/live/completion floors. Source contract/live describes the effective tool rule; external record fields separately identify the other floors. |
| evaluator_status | Host wrapper health. Production ready only after admission; injected failures are test seams. |
| topology | exclusive only while the runtime owns all the checks in section 5. No frame can set it. |
| state | Authenticated current W007 snapshot from the owner after expected-epoch comparison. Even a per-call-only bundle requires this state. |

Construct W001 canonical request bytes plus exactly one LF, then call DecodeRequest. ErrWire is a local refusal with no Result; LocalRefusal is fixture-only. Facts come from EvaluateBundle's exact `/params/arguments/request/amount_money/{amount,currency}` parsing and fixed currency table. The payment/key leaves identify the linked request and local replay hash only; they are not attested account facts.

C is the stricter of installed/profile/current live restrictions and **effective** mcptool.Decide. Do not intersect effective live allow with the original tool deny again. An unreadable required restriction is C=unknown. Current loadOverlay retains the last good overlay on read failure; add a health/revision-returning read for the business branch so unreadability cannot masquerade as a current known restriction. Keep the existing behavior for non-business traffic. Bind a revision containing contract hash, MCP overlay serial/content digest, live-block/fence revision and immutable topology generation. Policy writers and the admission owner need a common lock/linearization point: a revision must not change between the final recheck and send authorization. An atomic file replacement without this shared admission protocol is insufficient. The linearization point is durable admission; a later tightening stops later admissions and cannot undo a committed submission.

#### Map all 32 composition cells

`A` = `commitAndSend`, `H` = `holdBusinessCall`, `D` = `refuseBusinessCall`. These are proposed paths in business.go. A includes fresh recheck, durable intent and state commit; it does not mean a successful refund. D calls the existing JSON-RPC refusal serializer and sends no upstream bytes. H consumes a queue slot, asks the existing broker and sends nothing until completion.

| C | business allow | business none | business ask | business deny | missing | crashed | timed_out | nonsense |
|---|---|---|---|---|---|---|---|---|
| allow | A, source business | A, source contract | H, source business | D, source business | D, failure recorded | D, failure recorded | D, failure recorded | D, failure recorded |
| ask | H, source contract | H, source contract | H, source contract | D, source business | D, failure recorded | D, failure recorded | D, failure recorded | D, failure recorded |
| deny | D, source contract | D, source contract | D, source contract | D, source contract | D, failure recorded | D, failure recorded | D, failure recorded | D, failure recorded |
| unknown | D, contract.unknown | D, contract.unknown | D, contract.unknown | D, contract.unknown | D, failure recorded | D, failure recorded | D, failure recorded | D, failure recorded |

Slice 1 cannot discharge H: static asks refuse compilation and an effective live ask refuses ask-unavailable without forwarding or invoking the legacy broker. H becomes a supported hold only after the separate approval protocol and slice 3.

The four rows map respectively to frozen vectors x01..x08, x09..x16, x17..x24 and x25..x32. Use Result.Final/Compose for exact tie attribution: ask/ask and deny/deny choose contract; unknown is denial. In failure columns C=allow/ask has final source business; C=deny/unknown retains final contract tie attribution. **Every failure column also retains business deny `$evaluator` and evaluator.<status>**, even when contract wins. Do not erase that failure because another layer refused. The 32 frozen x01..x32 fixtures become relay tests asserting no/one write and whether a broker request exists, not only comparing strings. The other statuses queue_full, late_reply, wrong_binding, extra_reply, restarted and record_failed take D too. Bundle, adapter, state, topology, input and invalid-outer-request failures also take D, with the frozen precedence.

A business `none` never expands product coverage. Another server uses its own C. On this server a different tool can return pure none, but the immutable profile floor makes C=deny for that action (section 5). On the selected generic tool every unsupported dispatch is business deny, never none.

`refuseBusinessCall` keeps `mcptool.Refusal`'s JSON-RPC 2.0, matching id, error.code=-32001 and error.data.tego.{rule,reason}. Extend its reason-to-words projection to accept safe business context, keeping that shape. Example: `Tego refused the MCP tool make_api_request on square: submitted USD 120.00 exceeds the USD 100.00 per-call limit (refund-cap)`. Invalid money: `the submitted refund amount could not be read safely`. Lost state: `this run's refund counter cannot be recovered; start a new run for a new budget`. No raw arguments or remote error body enters a reason. A malformed envelope whose id cannot be trusted uses the existing null-id parse-error shape, not a guessed id. Machine reason enums and condition fields remain separate from prose. Missing evaluator/configuration at launch exits 125; a defense encountered at runtime refuses the call.

The wrapper checks EncodeResult and all echoed bindings, safe facts against the validated prepared call, enum/record shape and proposed reservation against current state before accepting a result. A panic is recovered at the call boundary and poisons the session. The monotonic 1000 ms watchdog refuses a late evaluation even if it later returns allow. It cannot safely kill a Go goroutine; abandon its result, block the route, and do not start a second evaluation on that run while the first can still run. A process crash relies on the kernel boundary and owner/worker lifecycle, not on an unavailable refusal goroutine. Re-admission can create a new evaluation session only with the same durable state; no automatic retry of the failed call.

#### Existing human approval, strengthened at its seam

Reuse `configureMCPAsk -> runner.askRequest -> ask.Broker.Request -> ask.sock -> askclient/runact.Answer`, the terminal notice/ask/approve/deny commands, and the dashboard's approvals card/POST. Do not build a second approval inbox or a direct browser-to-worker permission channel.

Today the relay asks op=mcp_tool, target=`<server> <tool>`, hold=request, rule and shim PID/TID. The broker default is five minutes; contract parsing permits longer configurations up to one hour. For business holds use the earlier of contract timeout, client/run cancellation and 300000 ms, starting at the held context's creation, not after the card appears. The socket's five-second exchange bound and dashboard answer's ten-second bound are not the hold deadline. No broker, queue capacity, disconnect, client death, stale identity, denial or expiry means refusal. Expiry uses ask-timeout and consumes no budget. Hold=request is already non-rememberable; keep `--always`, alternate files and partial approvals unavailable for this feature in both UI and broker.

Add an optional typed business context to broker/protocol requests and safe projections to ask/answer records. Existing requests retain their current wire forms. A business answer must echo its context digest; an old client omitting it cannot approve that request. Extend askproto's strict decoder, broker/wire shape parity tests, client and both front ends together. Existing per-packet credentials, launcher-pidfd validation, random nonce and peer.Refuse checks remain mandatory. Retain the authenticated actual answering UID/PID/start identity in the decision; the display string By is not sufficient authority for recomposition. This is personal local owner/root approval, not proof of a distinct person or team role.

Propose a separate `spec/approval/biz/v1/` before slice 3. Its digest preimage is precisely ASCII `tego.biz-approval.v1\n`, then a four-byte unsigned big-endian context-byte length, then canonical W001/W002 JSON context bytes, with no final LF. Its exact required keys are: version (integer 1); host_id, boot_id, run_id, agent_id, contract_hash, server, tool, dispatch, adapter, worker_digest, bundle_digest, call_digest, evaluation_id, original_request_frame_hex, restriction_revision, authority_revision, nonce, deadline_mono_ns (strings); authorized_uids (sorted decimal strings); business_asks (the exact ordered W025 array); and contract_ask (null or exactly {revision,rule,source}, all strings, source contract/live). business_asks has at most 32 exact {condition,rule_id} objects with condition threshold.ask; no omitted keys are permitted. authorized_uids has one or two unique uint32 canonical decimal strings sorted by numeric value. Evaluation IDs/deadlines use canonical uint64 decimal strings; digest fields use 64 lowercase hex; the nonce is 32 lowercase hex; original_request_frame_hex is lowercase hex of at most 524288 bytes. Other identifiers are bounded ASCII strings, with restriction/authority revision encoded as 64-hex snapshot digests; dispatch is the fixed string refunds.payment. Deadline is monotonic nanoseconds on boot_id. Canonical context bytes are capped at 2*524288+8192; safe detail sent to clients is capped separately at 16384 bytes and listed summaries carry only small safe facts/digest. Freeze these exact shapes, bounds and known digest vectors there; this is a protocol proposal, **not an existing v1 digest oracle**. Only the broker-owned volatile context contains original_request_frame_hex, including its framing LF and held state. It must never enter the record or browser. Browser/CLI receive its digest and a small safe display object, not request bytes, raw identifiers or the replay array. Bound context storage by the explicit context limit, 16 holds/run and 64 holds/queued calls per host. No W005 field is added.

The card shows: agent/run, exact server/tool/refunds.payment, submitted amount in units and integer minor units, currency, all asking rule IDs and thresholds, the hard per-call/per-run limits, currently reserved total and proposed addition with timestamp/revision, bundle/adapter revision, expiry, and the scope/uncertainty sentence. Buttons are `Allow this submission once` and `Deny`. State can move while the person reads: the card says approval grants no reserved capacity.

On an approved answer, retain the original context and digest, then reacquire the run owner, reauthenticate authority/topology, read current restrictions and state and evaluate the **same call** with a **new** evaluation ID. Changed call, bundle, adapter/worker, policy/restriction/authority revision, expired deadline or changed complete ask set invalidates the answer. A changed state revision alone is expected; compare against the original held context separately. Refuse any fresh deny/error. Discharge only that complete approved business ask set and the exact approved effective contract ask. Recompose all remaining floors; a kernel/completion denial remains denial. Do not change the pure Result into allow. If a per_run rule applies, the completion owner constructs the B036 reservation by checked addition from fresh validated facts/state after every fresh predicate passed; Result.Reservation is intentionally nil on pure ask. Commit atomically as below.

Example: total=0, cap=10000 USD minor, two 6000 calls both await approval. First approved call reserves 6000. The second, even if already approved, reevaluates total=6000 and denies per_run.exceeded. A person cannot raise the cap, release a prior reservation or reserve the other 4000 by answering. A new run is a new budget.

### 2. Contract bundle, compiler and authoring

Propose this additive exact-key mapping on one `mcp[]` entry in contract schema v0:

```yaml
mcp:
  - name: square
    command: ["/opt/tego/workers/square/node", "/opt/tego/workers/square/server.js"]
    tools:
      allow: [make_api_request]
    business_rules:
      version: 1
      topology: trusted-stdio-worker-v1
      worker_digest: '<64 lowercase hex, installed trusted manifest>'
      bundle_sha256: '<64 lowercase hex, computed from bundle_json>'
      bundle_json: '{"adapter":"square.refund.v1","rules":[{"codes":["USD"],"id":"currencies","kind":"currencies"},{"currency":"USD","id":"refund-cap","kind":"per_call","limit":"10000"}],"server":"square","version":1}'
```

The placeholders are explanatory, not runnable digest values. `bundle_json` is a YAML string containing canonical JSON content with no LF, not a YAML rule map. This avoids a second decoder coercing money/duplicates. The authoring service computes the actual digest and writes both fields. No mutable URL, latest file or ambient environment reference resolves a bundle. Inline bytes are enough for v1; content-addressed external objects can be a later explicit schema extension.

Change `spec/agent/v0/agent.schema.json`, pkg/spec/agent/{agent,schema,validate}.go and new business_rules.go; mirror exact closed schemas and refusal/value tests. Validate the scalar byte bound before allocating/decoding. Call the **existing DecodeBundle on exactly those bytes**, compare Digest, confirm server label and adapter/version, enforce rule/key/currency ordering and rule bounds, and report native diagnostics at that YAML scalar. Reject null/empty/unsupported mappings rather than silently dropping the feature. Validate tools present, stdio only, exact manifest command, profile/tier and recording prerequisites. Threshold support requires ask configuration and the slice-3 protocol; until then compilation rejects that kind explicitly. Slice 1 also rejects per_run/unsupported currencies and requires an explicit currencies rule exactly [USD] plus a USD per_call cap; removing that coverage guard is unsupported, not an uncapped first-profile configuration. Slice 2 unlocks per_run and the full closed four-currency table. The first profile can explicitly permit a canonical bundle of exactly two rules: one USD currencies rule and one USD per_call rule. The evaluator's existing complete vocabulary does not mean every runtime capability is enabled.

Offline compile validates the declared bytes, linked runtime capability set, exact command and trusted public worker-manifest pin; it does not certify the current host boundary. Worker installation manifests contain no secret values and can be read through a root-owned public catalogue. Only runtime admission can establish exclusive topology on the actual prepared run. The builder may save a syntactically supported contract with host readiness explicitly not checked; it cannot display that as an admitted run.

Contract.Canonical includes the mapping's exact bundle string and verified digest, topology and worker manifest digest, so Contract.Hash binds them. RuleTable gains an immutable compiled Business entry per server with opaque Bundle, canonical bytes/digest and trusted-worker requirements. Launch redecodes/rechecks and requires a one-to-one match between every loaded business_rules marker and compiled entry rather than trusting a caller-constructed table; the relay receives that compiled entry, not data reread from the authoring source. Record the contract hash and bundle/worker pins at run_start and every business decision binding. A bundle edit/removal never changes an active run, even under Adjustable mode.

The merge rule remains the current MCP concatenation plus duplicate-name refusal. Do not invent override-by-server merging that can remove an inherited cap. Empty/null is not disabling; explicit removal in a newly reviewed contract is a widening. Preserve absence for all existing contracts so their canonical bytes/hashes remain unchanged. Older binaries reject the new key through their closed schema. A bypass of the supported loader is not compatibility; runtime missing-compiled-business checks still refuse. Contract schema version stays 0 for this additive field under docs/VERSIONING.md; changing existing meaning/removing fields would require version 1. Bundle version 1, adapter revision, worker manifest version, approval protocol version and record minor are distinct identifiers. Meaning/default/limit/currency/canonical changes allocate a new business spec version per B059; do not edit frozen v1 to fit upstream drift.

`spec/contracts/v1` is the **CLI contracts catalogue output schema**, not the source contract. Add only a compatible optional summary there if contracts --json exposes business metadata; reject unsupported catalogue schema in its reader as today. Add shared compiled sentences in internal/check/compiledview, inforce and control/rulesview. Read-only /rules can describe the bundle before a switch editor exists; the advanced editor must validate it through the same compiler.

The planned A3-1 (integration planning evidence) says business rules as switches, shared compile/YAML/save and scripts-off operation. SPEC (integration planning evidence) supplies a switch component, not refund semantics. The older PLAN-2 example of payments.issue_refund is superseded by the frozen real adapter: label the control `Cap submitted Square refunds on this route`, show make_api_request/refunds.payment in Full view. Use four typed controls for per-call cap, per-run cap, currency set and threshold. Display integer minor units and fixed exponents; any major-unit editor parses exact decimal text, refuses extra precision and never uses JavaScript Number for money. Show a missing currency cap. Removal/increase/new currency/disabled hard limit is widening; use the existing preview-bound acknowledgement, source-base compare and guarded save. Opaque rule changes classify conservatively as mixed. No `Also apply now` for bundle changes; say `Next run` before save. Rust/Wasm preview uses sample call/state and cannot authorize saving or a live call; the server always runs DecodeBundle/compile. Scripts-off POST preview must offer equivalent validation.

`tego learn` currently proposes files, exec and network from recorded actions; Learner.Add does not learn MCP argument policy. It cannot discover a safe maximum, refund eligibility, all equivalent actions or permission to widen. Extend its shared proposal/save path to **preserve an existing valid bundle from the run's contract copy**, requiring the user to retain or explicitly remove it in a new contract. If absent, offer an unconfigured suggestion/link, not a learned cap equal to the largest observed refund. Do not learn raw argument/key/payment bytes. The builder's from-run draft and learn --save must write identical canonical bundle bytes through the shared proposal/registry service. Loss/unreadability of a configured bundle blocks that draft rather than emitting an apparently protected uncapped contract. Watch/learn and adopted runs cannot activate this topology; configuring business rules requires an enforcing launched run.

### 3. Cumulative state and durable admission

#### Owner and keys

This algorithm implements B032 through B041 and the external epoch requirement B062; B064 still controls deferred state diagnostics inside evaluation. Use one `business.Owner` in the root launcher's runtime runner, outside mcprelay.Service, the agent and the pure evaluator. It survives Service/session replacement. An in-process scheduler in each root launcher uses one host-wide root-owned registry and kernel file lock to arbitrate W017/W028 limits across launcher processes. Use a fixed protected /run/tego/business-scheduler registry in the initial host mount/cgroup namespace, with one immutable boot/generation identity, bounded owner/ticket entries and per-owner kernel lifetime locks. Under the common lock, check directory/file ownership and device/inode, authenticate each live owner by PID/start/pidfd and its lifetime lock, and atomically update waiting/outstanding leases before accepting or transitioning work. A torn/missing/replaced registry or unprovable owner lease refuses; it must not initialize an empty replacement while a business run may remain. Each owner independently retains the expected registry generation. Remove dead-owner tickets only after proving that process is dead and its unsent work cannot be revived. The registry owns no money and needs no cross-boot continuation because old runs end at a host crash. This adds no scheduler daemon or evaluator process to the request path. It must be present in slice 1; a singleton in one Service would not enforce host bounds.

The full owner identity is `(host, run, agent-id, contract-hash, bundle-digest, server, adapter, expected-epoch)`. A total is additionally keyed by fixed `(tool=make_api_request, dispatch=refunds.payment, currency)`. Agent and contract are immutable run-manifest bindings, not caller-selected sub-budgets. W007 projects just run_id, bundle_digest, server, epoch, revision, totals and seen_keys with status. Do not add agent/tool/currency fields to that closed outer state binding. There is only one modeled dispatch, hence no ambiguity about which total W007 means.

The replay set is SHA-256 of each admitted idempotency_key's exact ASCII bytes, **shared across currencies and all connections/workers for this run/server/bundle**. It is not keyed by client PID, connection, rule ID, JSON-RPC id or amount. Maximum 4096 entries, no eviction. Increment state revision once per admitted call, even if there is no matching per_run rule. A matching run cap reserves once per currency, not once per rule. No applicable run cap means reservation=null but still consumes the key/revision. Pinned bundles mean caps cannot appear mid-run and require reconstructing an earlier uncapped total. Two different runs have distinct budgets by definition.

#### Use the record as the journal, with an independent continuity checkpoint

Avoid a second database and a record/state dual write. The authoritative journal is the existing hash-chained `events.jsonl`, with a new single `mcp` business-intent line containing the complete atomic state delta: before/amount/after if reserved, admitted key digest, prior/next revision, operation/evaluation IDs and all immutable bindings. State is the fold of these committed intent lines, not allowed/evaluated/response lines. Do not persist a mutable totals cache as authority.

Add `Writer.AppendBusinessDurable` (proposed) which validates/redacts a safe payload, takes the writer lock, appends the one complete intent line, and fsyncs events plus required run/parent directories before returning its seq/id. Existing Append and AppendBatch remain insufficient. A torn line or uncertain sync poisons the business owner; ordinary truncation/recovery must never reset a business run. Reaper and sweeps must identify the business marker before any resuming Writer is opened, preserve uncertain journal/checkpoint bytes and refuse automatic tail truncation, zero reconstruction or a clean business coverage seal. No raw argument/response blob is involved. Do not let redaction or blob splitting remove a state-binding field: validate the final stored shape before the acknowledgement. The ledger cap and disk errors must refuse admission, not drop an intent. Amend docs/p0/record-ledger.md R6 for this explicit business fsync exception; ordinary event writes keep their existing policy.

Independently retain a root-owned continuity manifest/checkpoint under proposed machine `business_state_root`, default `/var/lib/tego/business/<host>/<run>/`, outside the ledger and all agent grants. Directory creation/open uses pinned descriptors, no symlinks, root ownership and non-writable ancestors. The immutable run manifest contains run/agent/contract/bundle/server/adapter/worker binding and a freshly generated epoch; the mutable checkpoint contains epoch, latest business revision, journal intent seq/id, evaluation-ID high water, session generation and a poison flag. Write temp, fsync file, atomic rename, fsync directory; compare under one exclusive run lock. The live owner also keeps the expected epoch independently in memory. State provenance here is root ownership, verified descriptors and hash-chain/checkpoint binding, not an evaluator assertion. A host/root administrator and honest storage remain trusted.

Create the initial manifest, explicit zero state and checkpoint with O_EXCL **only before admitting a new run**; durably bind the same epoch/pins in run_start. Never run this initialization on a missing state file for a run that already exists. Starting a new run explicitly creates a new budget and says so. Never reuse run IDs/epochs; deleting old state is not permission to reuse them. No rollback/recovery from a backup of just the ledger, no guessed zero, no fresh epoch during a Service restart. Keep active state protected from gc/retention; cleanup follows final run closure and the evidence retention policy, not relay lifetime.

The journal and checkpoint are not a general distributed atomic transaction. Their ordered protocol is safe because **nothing is sent until both are durable**. A mismatch at any crash boundary blocks the route; the design sacrifices availability, not budget. Do not use a best-effort mirror or append an allow and hope a later checkpoint catches up.

#### Admission algorithm and linearization

1. Admit the actual peer/session; acquire host queue capacity atomically and the run's single-evaluation slot. A run can have 16 waiting calls (including holds), one outstanding evaluation; at most 16 active runs and 64 total waiting calls per host. Idle runs do not consume active slots. Moving evaluation to hold must acquire its waiting slot atomically or refuse queue_full. Transitions count the call exactly once; extra connections do not acquire separate budgets.
2. Acquire the owner's run lock. Verify live topology/worker and all immutable bindings. Compare journal state epoch with the independently retained expected epoch **before constructing a Request**. Require the trusted current checkpoint and complete recoverable journal; lost/unavailable/poisoned state refuses the route, not just a single input. Allocate the next evaluation ID and persist its high water before use. Failure poisons; never wrap uint64. Build current W007 ready state, strict canonical call and current C/restriction revision.
3. Call DecodeRequest and EvaluateBundle in process under the monotonic watchdog. Validate all result bindings and shape. On deny/error, append the single safe refusal synchronously; no key, total or budget revision changes. Inability to record it poisons coverage and blocks further calls. On ask, record/publish the bound hold, release owner/evaluation locks, retain a host waiting lease and reserve no money. Completion returns through step 2 with fresh state and the section-1 discharge rules.
4. For final allow, recheck owner revision, topology and effective restriction generation under the same admission lock used by policy updates. A conflict discards the proposal and requires a fresh evaluation ID/current state, never stale send. Bound conflicts by the call deadline/queue policy; no upstream request is retried. Reject reused key, capacity, revision or sum overflow before commit. For direct allow validate the returned Reservation against fresh state; approved asks use B061 checked bookkeeping. Reserve the pending session/JSON-RPC-ID capacity (16/run, 64/host) before step 5. A pending reuse or failed slot reservation refuses without an intent. Checkpoint/allocation state is not an authorization grant.
5. Invoke the durable journal append for one intent that atomically consumes the key, any cumulative reservation and next revision. While the admission lock is still held, durably move the independent checkpoint to that exact intent seq/id and next revision. Only after both acknowledgements publish the new in-memory state and an unforgeable, single-use dispatch token bound to operation, worker session and call digest. This is the admission linearization point. A failure at either persistence step refuses sending and poisons the route. If an intent might be durable, retain its reservation conservatively; do not describe it as a normal predicate denial that spent nothing.
6. Record delivery-attempted durably before using the token; recheck cancellation and required boundary before the write. The trusted relay owns the worker stdin descriptor and writes exactly content+LF once under the fixed 1000 ms monotonic deadline. Independent cancellation closes the channel or signals the guardian without taking the admission lock; full/partial pipe witnesses must terminate. Never wait for a remote response under that lock. A canceled or lost boundary after commit sends nothing and retains admission. A partial/error/deadline write is failed/uncertain, never retried. Record write-accepted only when the complete local write succeeds; this says nothing about remote completion. The dispatch token cannot be reconstructed from an events line or presented by the agent. No journal replay dispatches anything.
7. Read the real trusted worker pipe, correlate the pending JSON-RPC id within its pinned session, record only classified response metadata, then forward the response to the client. Correlation IDs are separate from evaluation IDs. One trusted worker per stdio client session avoids rewriting frozen JSON-RPC ids; all those workers share the owner/counter. Bound pending response IDs separately (proposed 16/run and 64/host), reject reuse while pending, and never use agent-provided S frames as server evidence. Unknown/duplicate/late response yields remote unknown, no resend. A known server error may be recorded as reported error; no body or secret goes to the ledger.
8. Outcome append failure blocks further affected calls, sets the root checkpoint poison flag if possible, and leaves remote outcome unknown. If even poisoning cannot be persisted, stop the run, close/kill workers and disallow continuity. The run-end business coverage seal is omitted unless every required business event was durably recorded. Missing seal means coverage unknown, so a failed denial/outcome record cannot silently become a clean receipt. A live receipt is provisional. Generic run_end alone is insufficient.

The owner must retain the final admission/policy lock through token consumption and the one local pipe write; policy updates linearize either before this final evaluation or after the write attempt. Use the fixed lock order owner/policy, then ledger writer, never the inverse. This keeps the revision/boundary transition precise; it must not retain that lock while waiting on a person or on the remote response. Every connection goes through the same owner. To qualify concurrency, use two clients and two workers, both attempting 6000 against 10000: exactly one commits, one refuses, total=6000. Multiple matching per_run rules still create only one delta. Test both completion orders with two approved holds.

#### Restart, crash and failure table

| Failure point / condition | What is durable or known | Required behavior and budget |
|---|---|---|
| Before initial epoch/run_start/checkpoint is durable | No admitted business run | Exit 125, release no agent/worker authority. Never recover it as zero for an existing run. |
| Service/session restart with healthy runner | Independent expected epoch survives; journal/checkpoint verified | Explicitly admit a new session, recover totals/replay/evaluation high water; cancel every old hold and unsent token. No automatic replay. Slice 1 may simply refuse continuity; slice 2 supplies this recovery. |
| Before commit, including denied/expired hold | No intent/key/reservation | Send nothing, spend nothing. Recording failure poisons coverage. |
| Write/sync of intent fails or crashes | A complete intent may exist, or a torn suffix | No send. Do not decrement or truncate to a permissive state. Poison/unknown; route remains blocked this run. |
| Intent synced, checkpoint not durably moved | Journal can be ahead | No send was authorized. Recovery refuses the mismatch; conservatively retain any complete reservation. |
| Checkpoint moved, before attempted/write | Intent/key/reservation retained | A clean restart recovers the consumed budget. Mark delivery not attempted if known; after a process crash conservatively unknown. Never send from recovery. |
| Attempted persisted, before or during pipe write | Full admission retained | Remote may or may not have acted. Unknown/failed delivery, no release and no retry. |
| Full local write, no response / upstream timeout | Admission retained | Record local acceptance and remote unknown. Client gets failure/unavailable as appropriate. The budget stays consumed. |
| Worker/API reports an error, including definitive refusal | Admission retained | Record reported error; **no refund of budget** under B039. A new unique-key attempt is a new admission if capacity remains. |
| Worker reports success | Admission retained | Record reported success only; no settlement/compliance claim. |
| Outcome recording fails after send | Send cannot be undone | Block more affected calls, poison state/coverage; no clean coverage seal. |
| Replay / 4096 keys / exhausted revision / overflow | Valid current state | Frozen state.replay/state.capacity/per_run.overflow denial. No eviction, wrap or partial state. |
| Two calls race | One run lock plus revision CAS | First commit consumes capacity; second reevaluates. No last-writer-wins totals. |
| Checkpoint missing, wrong epoch, journal truncated/replaced, corrupt chain, stale restore, ledger/state inaccessible | Continuity unproved | Refuse **before evaluation**, poison route for the rest of the run. Never initialize a replacement epoch. |
| Runner/host crashes | Old in-memory state and holds are gone | Retain durable evidence. Worker guardian must close/kill on control-owner death; existing run is ended/orphaned, not transparently relaunched. No full-host automatic continuation in v1. A new run is an explicit new budget. |
| Host registry disappears or lease is uncertain | Aggregate capacity cannot be established | Refuse new work and cancel holds, never allow by creating a second empty registry. Recovery revokes the old generation and requires cancellation/acknowledgement of every old lease from all verified live owners before issuing new leases; uncertainty refuses. |

**Fail-closed argument.** Every actual worker write requires a fresh in-memory dispatch token. Minting it requires valid current state with epoch equal to an independent manifest/memory pin, all restrictions passing, and both journal/checkpoint durability acknowledgements. Replay consumes the token; it cannot be minted by reading old intent records. Losing any state or continuity witness removes a token prerequisite and blocks the route. Recovery never invents zero and never resends. Since each committed per_run addition is positive, checked and never released after uncertain delivery, recovered totals cannot be smaller than successfully acknowledged admissions under the trusted-storage threat model. Disk corruption/rollback of one side is detected by chain/revision/head comparison. A trusted administrator restoring **both** authorities or storage lying about fsync is outside this host-trust proof; do not claim resistance to a dishonest root host.

## Alternatives

Reusing the in-run shim cannot establish exclusive worker memory, channels or
credentials. A per-call comparison alone still leaves replay and uncertain
submission unowned. An in-memory counter or asynchronous admission event cannot
provide durable continuity. Running Rust as a live helper would add a request
process contrary to B063. Trusting caller-supplied readiness, schema or state
would make the agent the admission authority. Reject these shortcuts rather
than treating them as a weaker first slice.

## Consequences and acceptance

The first useful artifact is an offline guest qualification profile. The host
administrator and honest storage remain trusted. Uncertain state sacrifices
availability for the rest of a run; no recovery invents a zero budget or resends
an intent. The cap and condition can be probed intentionally. No result or
receipt establishes settled money effects or universal business compliance.

### Allocations and provisioning

Record minor 38 and ADR 0152 were allocated; ADR 0151 remains the feature semantics record. The host administrator provisions the dedicated service UID, root-owned immutable public worker catalogue, root-only installed-worker secret source, persistent business state root and boot-scoped scheduler registry. The root launcher validates their ownership and held descriptors and is the admission authority. Missing provisioning refuses; contracts never provision or choose credentials. Slice 1 uses synthetic credentials and an offline fixture manifest. Installed-server activation stays disabled until slice 4 qualification.

Build order is capability proof, slice 1, slice 2, slice 4, slice 3, slice 5. The target guest is pinned Ubuntu 25.10 / Linux 6.17 amd64 with BPF LSM and the required decision plane actually active. ### Slice-1 requirements settled by review

1. Policy writers (`mcptools.Update`, liveblock and fence writers) participate in the same root-owned admission lock/generation protocol as dispatch. Lock order is owner/policy then ledger. A cross-process writer cannot acknowledge a tightening without that lock. File rename alone is insufficient. Race witnesses pause immediately before final recheck, intent, and write; tighten from a second process; assert either tightening wins and zero bytes are sent, or one earlier committed submission wins and all later calls refuse. Unknown writer health/revision refuses. This is slice 1 work.
2. Legacy protocol 3 refuses a business server before child/stage admission or any C/S frame; HTTP configuration and every HTTP handler entry refuse it before forwarding. No fallback to legacy shim startup exists.
3. The control grammar below is closed. Startup must complete verified initialize and tools/list on trusted worker pipes before a call can be admitted. `notifications/tools/list_changed`, schema drift, worker EOF, unexpected server request or any unsupported server notification immediately withdraw readiness for the remainder of this run. No silent re-handshake or cached-schema continuation.
4. A local worker write has a fixed **1000 ms monotonic deadline**, starting before lock acquisition for final admission. Use a nonblocking pipe with poll/deadline and an independently cancelable owner; cancellation closes the worker channel or signals its guardian without acquiring the held admission lock. Check cancellation before commit and immediately before write. Never wait on a remote response under that lock. A partial, canceled or late write retains the intent, blocks the route and is never retried. Test a full pipe, cancellation and concurrent tightening; every wait terminates within the bound plus scheduler tolerance without requiring the policy lock for cancellation.
5. Reserve response-ID capacity (16/run, 64/host) and the session/id binding **before intent commit**, alongside queue and worker capacity. Pending JSON-RPC-ID reuse refuses. Release on a validated terminal response or session teardown, while retaining the durable replay key. A failed reservation sends nothing and writes no intent. Unexpected, duplicate and late response IDs poison readiness.
6. Reaper and sweeps inspect the immutable business marker before opening a resuming writer. For a business run, torn/missing journal/checkpoint, corrupt chain, replaced inode or uncertain ownership means preserve all bytes and refuse automatic repair/continuation. Do not call the ordinary Writer.resume truncation path, emit a clean business seal, recreate zero state or allow retention to erase active evidence. Test both reaper and sweep against torn and complete-but-uncheckpointed intents. Existing non-business recovery remains unchanged.
7. **No-root tier:** slice 1 requires the root-owned continuity owner, scheduler and separate worker identity even for a per-call cap. It refuses all business-bearing contracts there: `business rules require the root-owned trusted worker and durable admission owner; this tier cannot establish them`. The integer comparison itself needs no privilege; exclusive-route admission does. There is no silently weaker per-call mode.
8. Human-readable cap and condition disclosure is intentional. Agents can probe the configured limit and observe refusals. This is not an indistinguishable refusal channel. Do not disclose identifiers, arguments, remote bodies or credentials.

### Frozen slice-1 control-message grammar

All messages are single bounded UTF-8 JSON objects, duplicate-free at every depth, literal keys, no unknown keys, canonical positive safe-integer request IDs and `jsonrpc:"2.0"`. Batches, call notifications and arbitrary responses from the agent refuse. Calls retain the stricter frozen A019/A020 grammar. Control IDs use a separate pending table and may not collide with call IDs. Fixed fixture protocol revision is `2024-11-05`; the fixture must advertise precisely the pinned tool registration and no server action-delegation capability. Actual installed dependency/handshake qualification remains slice 4 work.

| Direction | Exact admitted shape and transition |
|---|---|
| client initialize | `{id,jsonrpc,method:"initialize",params:{protocolVersion:"2024-11-05",capabilities:{},clientInfo:{name,version}}}`; name/version bounded printable ASCII strings 1..64; only once, first request |
| worker initialize result | `{id,jsonrpc,result:{protocolVersion:"2024-11-05",capabilities:{tools:{}},serverInfo:{name:"square-mcp",version:"1.0.0"}}}` with matching ID; fixture provenance separate from the server label |
| client initialized | `{jsonrpc,method:"notifications/initialized"}` exactly once after initialize result |
| client tools/list | `{id,jsonrpc,method:"tools/list",params:{}}` once after initialized; no cursor/pagination |
| worker tool list | `{id,jsonrpc,result:{tools:[{name:"make_api_request",description,inputSchema}]}}`; description and schema must match exact pinned fixture manifest bytes/digest; no other tool, cursor or capability |
| client ping | `{id,jsonrpc,method:"ping",params:{}}` only after initialized, bounded pending capacity |
| worker ping result | `{id,jsonrpc,result:{}}` with the corresponding pending ID |
| client tool call | A019/A020, only after verified list; no legacy non-call pass-through |
| worker call response | `{id,jsonrpc,result:{content:[{type:"text",text}],isError}}` with exact pending call ID; text bounded by frame limit, isError boolean; report status only, never persist text |

Tool description/schema contents are manifest pins, not inferred from live input. An error to initialize/list/ping withdraws readiness and refuses further calls; no retry. Other client control messages refuse locally. Unsupported worker messages withdraw readiness before another admission. This grammar intentionally restricts generic MCP; installed support must qualify its exact revision and cannot widen this table by convention.
