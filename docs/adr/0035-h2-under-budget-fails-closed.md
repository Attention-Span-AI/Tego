# ADR 0035: h2 and unanswered requests under a budget fail closed on the uprobe path

Status: accepted; implemented 2026-09-24: internal/runtime/capture/uprobe (handle reports an h2 connection through loseConn; handleClose, a count restarting at 1 and Stop report waiting requests through closePending), pinned by unmetered_test.go. Amends docs/p0/limits-check-doctor-cli.md R1 and docs/p0/capture-derive.md R7a and R17.
Amended by ADR 0037: decision (2) is one rule for both capture paths.

Decision: (1) On the uprobe path, an h2 connection (capture-derive.md R17's gap) is reported unmetered (runtime.ReportUnmetered), which ends a run with a token or cost budget, when its peer is a model host (a models[] entry or a host the parsers claim) or a host capture never learned. The rule is the one a lost connection already follows (loseConn): the Host of each request waiting on the connection, or with none waiting, the connection's last Host. A preface on a fresh connection names no Host, so it is reported. An h2c upgrade from a learned non-model host stays exempt. (2) A request to a model host, or to an unlearned host, whose response capture never saw when its connection ended cleanly (an SSL_free close record, the kernel's per-connection count restarting at 1, or the source's Stop) is reported unmetered the same way. A connection with nothing waiting reports nothing. (3) The source only reports. Whether a report ends the run is the runner's (runtime.captureUnmetered): only under a token or cost budget.

Why: [documented, code: uprobe.go handle, before this ADR] ErrHTTP2 called dropPending without reporting, and limits-check-doctor-cli.md R1 listed h2 as a loss that does not end a budgeted run. [observed] curl built on OpenSSL negotiates h2 with api.anthropic.com, so a budgeted run whose agent calls the model API with curl spent tokens the budget never saw. [documented, code] handleClose and Stop called dropPending, so a request whose response never arrived before a close or a stop left no report, though its spend was as uncounted as a lost connection's. A budget that is silently not enforced is the failure a budget exists to prevent; the rule is that budgets fail closed.

Security argument: Fail-closed by construction. The source cannot read h2, so it cannot tell a model call from any other exchange on that connection; what it can tell is the host, when it learned one. Unknown counts as a model host, as it already does for a lost connection (meteredHost), so the table losing track of a host can only end a run, never hide spend.

Options considered:
- Keep h2 unreported (the prior rule): model spend over h2 goes unmetered under a budget. Rejected: it is the defect.
- Learn the peer from the handshake's SNI (a probe on SSL_set_tlsext_host_name / SSL_ctrl, or on the ClientHello), so an h2 connection to a known non-model host is exempt and only model hosts end the run. Rejected for now: a new probe, a new ring record kind and a per-SSL* host table, each with its own attach and loss paths, for a narrower false positive. It stays the way to shrink the cost below if it bites.
- Read h2 (HPACK, frames) on the uprobe path: out of scope for P0 (R17).

Consequence: The cost is stated: benign h2 traffic to a host capture has not learned (a fresh h2 connection to a package index, a git host, any h2 peer) ends a run with a token or cost budget captured through uprobes. A run with neither budget is unaffected: its record carries the h2 gap as before. The forwarder path is unaffected: its listeners speak HTTP/1.1 only (R19). An agent that must use h2 to non-model hosts under a budget runs through the forwarder, or waits for SNI learning. Unanswered requests at a close or a stop now end a budgeted run where they passed silently; an agent killed mid-request by another limit already ended its run, so the report changes nothing there.

*Amended 2026-09-24:* (2) is now one rule for both capture paths, recorded in ADR 0037: the forwarder reports a request that got no response bytes unmetered as well (a dial failure alone exempt), and on the uprobe path the rule also covers a request with an unreadable target at a close (`closePending` counts it as `loseConn` does), one a later response showed would not be answered, and one the pending table evicted. A CONNECT tunnel opened to a model host is reported by (1)'s reasoning: the TLS inside it is a session capture cannot tell it reads.

*Amended 2026-10-05 (the 2026-10-04 proxy work):* the Consequence's "its listeners speak HTTP/1.1 only (R19)" holds by default only. A contract that sets `net.proxy.http2` (explicit `capture: forwarder`, declared `models[]`) makes a forwarder listener also accept HTTP/2 by prior knowledge, and each HTTP/2 model request keeps the forwarder's capture accounting, so a budget sees it ([proxy protocols](../p0/proxy-protocols.md) R2). CONNECT and WebSocket grants are opaque to accounting and refuse token, cost and repeat ceilings before the agent is released (same rule). This ADR's decisions concern the uprobe path and are unchanged.
