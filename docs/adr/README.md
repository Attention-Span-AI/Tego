# Architecture decision records

One file per decision, numbered in order of writing. Each ADR opens with a `Status` line (`proposed` or
`accepted`, the date, and what is implemented), then its Decision, Why and Consequence.

**Editing policy.** An accepted ADR's decision text is not rewritten. A later change is recorded in one of two ways:

- A decision that changes the old one is a new ADR. The new ADR names what it supersedes or amends on its
  `Status` line, and the old ADR gets a forward link under its own `Status` line (`Superseded by`, `Superseded in
  part by` or `Amended by`, naming the new ADR).
- A correction of fact, or a refinement that keeps the decision, is appended to the old ADR as a dated note,
  `*Amended YYYY-MM-DD (source):*` (older notes read `Amended YYYY-MM-DD:`), below the original text. The note
  says what changed and why, and never replaces the text above it. A forward link naming a `proposed` ADR says so:
  the older decision stands until that ADR is accepted.

The specs under `docs/p0/` state the current rule instead, with a dated Changes list per section (ADR 0030 (6)).

**Numbering gaps.** Numbers are never reused. A number not in this table was reserved and not used, or is not published here.

**Index.** Status as each ADR's `Status` line gives it. "Later changes" lists the forward links and whether the
ADR carries dated notes.
