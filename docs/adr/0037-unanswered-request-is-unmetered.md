# ADR 0037: a model request that got no response bytes is unmetered, on both capture paths

Status: accepted 2026-09-24; implemented in internal/runtime/capture/forwarder (listener.go derive, dialFailed) and internal/runtime/capture/uprobe (events.go unanswered, emitResponse, emitRequest; uprobe.go closePending). Amends ADR 0035 (2) (now one rule for both paths), capture-derive.md R7a and limits-check-doctor-cli.md R1. Distinct from ADR 0036, which it leaves as it is.

Decision: (1) A request to a model host, or to a host capture never learned, that got no byte of a response is reported unmetered (`runtime.ReportUnmetered`), which ends a run with a token or cost budget. "No byte of a response" means no status line: on the forwarder, the upstream round trip returned an error, or the run ended with the exchange in flight; on the uprobe path, the request was still waiting when its connection ended (closed, restarted, gapped, the source stopped), when a later response on the connection showed its answer would never come, or when the per-connection table of waiting requests gave it up. (2) One exemption, forwarder only: an upstream leg whose dial failed (`*net.OpError` with `Op == "dial"`) sent no byte, and is not reported. Every other failure, a TLS handshake's included, is not told apart and is reported. (3) Once any response byte has arrived, ADR 0036 applies: a stream interrupted after `message_start` is charged the request's `max_tokens` as a bound and the run goes on; only a stream with no known `max_tokens` is unmetered. So an interrupt before the first response byte ends a budgeted run, and an interrupt after `message_start` does not.

Why: [documented, code before this ADR] The two paths disagreed. The uprobe path's `closePending` reported a waiting request unmetered (ADR 0035 (2)); the forwarder, on a round-trip error, called `finish(x, nil)`, and derive's nil-response branch recorded one `gap why=malformed` and nothing else, so a budgeted run went on. [inference] The upstream reads the request before it answers: a connection it drops after reading the prompt, or a client that leaves while the model is generating the first token, may have been billed for the whole input and some output. Nothing on the wire says how much. A budget that is silently not enforced is the failure a budget exists to prevent, and one rule for both paths is the one that holds whichever captures the run (limits-check-doctor-cli.md R1).

Distinction from ADR 0036: ADR 0036 bounds an answer that has begun. Its `message_start` states the input and cache counts, and the request's `max_tokens` bounds the output, so the charge is an upper bound and the run can go on. Before any response byte there is no input count, no model and no id; `max_tokens` bounds output only, so no bound exists for what a request with no answer cost, and it is unmetered. The large-body case of ADR 0036 (2), a `max_tokens` derive could not parse from a body capture kept as a prefix, is now read off every byte of the body (capture/maxtokens) and bounded, so it no longer ends a budgeted run.

Options considered:
- Keep the forwarder's gap-only behaviour: the forwarder, which R38 makes the agent's only route to the model once capture is active, would pass exactly the loss the uprobe path ends a run for. Rejected.
- Report dial failures too (no exemption): fail-closed without exception, but a dial failure is the one case where the leg provably sent nothing (net/http returns the dialer's error before a byte is written), and an agent's SDK retries it as routine; ending a budgeted run at every transient DNS or connect failure would make budgets unusable for no spend. Rejected.
- Charge `max_tokens` plus the request's size as a bound instead of ending the run: input tokens cannot be bounded from bytes without a tokenizer, which is a model-side estimate Tego does not make (ADR 0003). Rejected.

Consequence: A user interrupt before the first response byte (Esc while a coding agent is waiting on the model) ends a run with a token or cost budget; after `message_start` it does not. An upstream that drops connections without answering ends budgeted runs. A run with neither budget is unaffected: its record carries the gap as before. On the uprobe path the same rule now also covers a request dropped because a later response showed it would not be answered, and one the pending table evicted; both were silent. `closePending` counts a request with an unreadable target as `loseConn` does.

*Amended 2026-09-24:* the `capture/maxtokens` package named above was removed; the one
streaming `max_tokens` scanner is `anthropic.MaxTokensScanner` in derive/anthropic, and httpstream reaches it through
`Options.BodyScanner`, which capture wires. The rule is unchanged.

*Amended 2026-09-24:* (1) An unanswered request whose path the deriver classifies as spending nothing (derive/anthropic `classifyPath` silent: `/`, anything outside `/v1` such as `/api/...` telemetry, `/v1/messages/count_tokens`, `/v1/models`, the Files API, a batch's status) is not reported, on either path: both ask the deriver (`derive.SilentPaths`, `Dispatcher.Silent`) before reporting. An unknown or ambiguous path (`/V1/messages`, an unreadable target, a tunnel, a host capture never learned) still fails closed, and a lost uprobe connection still counts what it would have carried next, so an h2c upgrade's silent `GET /` does not exempt the h2 after it. (2) An unmetered report that arrives after the agent's main process has exited (awaitExit reaped it) — typically a request tego's own shutdown aborted, the cgroup kill or the forwarder's Close — records `gap what=capture why=unmetered-after-exit` with its count and changes neither the end reason nor the exit code: a budget can no longer be enforced on a run that has ended. Before the exit nothing changes. (3) Under a `cost_usd` budget, a response reporting server-tool requests to a price table that names no `server_tool_per_request` fee at all is unmetered (the watcher reports it through `limits.WithOnUnmetered`), where it was charged $0; `tego compile` warns `[unenforced]` for such a table. Implemented in internal/runtime/capture/forwarder (listener.go silent, markNeverSent), capture/uprobe (events.go unanswered, loseConn), runtime (unmetered.go, run.go quiesced) and limits (price.go UnfeedServerTool, watcher.go).

*Amended 2026-09-24:* point (2) of the note above was too
wide. awaitExit marked the run exited once it reaped the main process, before it waited for the cgroup to empty, so a
descendant that outlived the main process (`sh -c 'agent & exit 0'`) could spend with every unmetered report, the
unfeed server-tool one included, reduced to a gap. The exemption now applies only once the run has quiesced: its
cgroup is empty (awaitEmpty), or tego's own teardown has begun (the kill awaitExit or awaitEmpty sends when the run's
context ends, or shutdown). While the cgroup is populated a report fails closed (reason `error`, the tree killed) as
before the main process's exit. Implemented in runtime (run.go `quiesced`, run_shutdown.go, unmetered.go).

Note 2026-09-29: the silent classification of that note's point (1), "anything outside `/v1`", is `api.anthropic.com`'s. On another host a `models[]` entry declares for provider `anthropic`, only the root path and `/api/...` paths with no segment inside `/v1` are silent; a gateway's prefixed Messages path (`/anthropic/v1/messages`) is a path the parser does not read, and unanswered it is reported (capture-derive.md R25; `derive.HostScoped`).

Note 2026-09-30: a response whose usage carries a billing modifier the price table has no rate for (speed, service_tier, inference_geo other than the plain value, or iterations beyond one message) is unpriced and, under a cost budget, charged at twice MaxCost (usage.modified; limits-check-doctor-cli.md R2). Extra iterations bill attempts the counts omit, possibly at another model's rates, and are the residual no charge bounds.

Note 2026-10-03 (superseding the 2026-09-30 residual): a response whose usage carries a rate modifier the price table has no rate for (speed, service_tier or inference_geo other than the plain value) is unpriced and, under a cost budget, charged at twice MaxCost (`usage.modified`; limits-check-doctor-cli.md R2). Extra or unreadable `iterations` additionally make accounting incomplete and the exchange unmetered: those attempts may be omitted from the top-level counters, so twice MaxCost cannot bound them. Observed usage and `modified` remain in the record, but a token or cost budget fails closed; a later final output count cannot recover that missing spend. Absent, null, empty or one unambiguous exact-case `type: message` iteration remains metered (`TestExtraIterationsKeepKnownUsageButCannotBoundSpend`, `TestPlainIterationsRemainMetered`; parser version `anthropic-2026-10-3`).
