# ADR 0040: protected write targets need a kernel decision plane, and a forwarder model's port is closed around the forwarder

Status: accepted 2026-10-05, as the record of two rules implemented 2026-10-03 by spec text alone. Their cost to users (Consequence) is a product-scope question that ADR 0041 later settled. Amends ADR 0002 (tier 1 no longer runs every contract) and ADR 0021 (5) (the fallback's best-effort `deny_write` refusal is no longer an admitted mechanism). ADR 0024's Consequence closed R15c's race only where a plane mode loads; with (1) every run that may start with such a contract is one of those. Specs: enforce-landlock R5a and C7, supervisor R15c, agent-contract R20, SEMANTICS §1 and §2, spec/backend/CAPABILITIES.md.

Superseded in part by ADR 0041 (accepted 2026-10-05): its D1, decided (a), makes (1)'s launch refusal the opt-in `fs.assurance: kernel`; by default tier landlock and tier cgroup's listener run such a contract with the supervisor's best-effort refusal, disclosed.

Decision: (1) A compiled table whose built-in `deny_write` set (agent-contract R20: git hooks and config, harness and editor settings, shell startup files under a write entry) is not empty runs only with a kernel decision plane: tier cgroup with an `lsm` or `fmod_ret` plane mode, or tier bpflsm. Tier landlock, and tier cgroup with only the fanotify listener, refuse it before the child starts: `enforce.Select` returns no backend with a `tier-unavailable` diagnostic naming the first target, and the Landlock `Prepare` fails with `ErrNegativeWriteNeedsPlane` before it builds a ruleset, so `tego run` exits 125. The seccomp supervisor's pathname refusals of those targets (R15c) stay as early refusals and records where it is notified; they are not an enforcement fallback. A contract keeps tier 1 by narrowing `fs.write` to directories that contain no target, or by naming a target in `fs.write`, which removes it from the set (R20's opt-out).
(2) Under `capture: forwarder` the model endpoints a contract's `models:` declares are reachable only through the forwarder's listener. A known endpoint address, and its local aliases (loopback, the unspecified address, this host's own addresses), is refused even when `net.allow` names it (`rule: models[<host>:<port>]`). For a model declared by a non-localhost name, every destination on the model's port that no `net.allow` entry names is refused too (`rule: models.port[<host>:<port>]`), with or without a `net:` section; other ports keep ordinary policy. `compile` warns `model-port-restricted` when no `net:` section exists and `model-direct-bypass` for a `net.allow` entry that names a model. `capture: uprobe` and `off` keep ordinary policy; at tier landlock a uprobe capture is lowered to forwarder (`RuleTable.AtTier`), so the rule applies there by default.

Why: [documented, the earlier spec text, SEMANTICS §2] the tier-1 refusal of a `deny_write` target was "best effort, not a closure": the kernel reads and resolves the path again after the supervisor continues a write it decided elsewhere, so a sibling thread that rewrites the path string, or a peer that swaps a symlink or directory between the two lookups, lands the write in a target. [inference] A write that lands in `.git/hooks` or a shell startup file is code the user runs later outside any run, so the race is a way out of the contract, not a missing record. [documented, Landlock] Landlock cannot refuse beneath a write grant, and enumerating write grants around a target would refuse creating a file at every level above it (`.git/index.lock` on every commit). [documented, ADR 0024] the plane decides on the inode the kernel resolved, so the race does not exist there.
[documented, the earlier SEMANTICS §1, "What this does not refuse"] the earlier guard refused a model endpoint by the addresses the supervisor resolved. An address the agent's own resolver returned and the supervisor's lookup never did reached the model directly, and a `net.allow` entry naming the model admitted it as "the author's explicit choice". Both are model traffic the forwarder never sees: unrecorded, and spend a token or cost budget never counts. [inference] A remote service cannot be told apart by an address that differs from this process's own DNS answer, so the guard closes the port rather than the addresses.

Security argument: Both rules fail closed and loudly. (1) replaces a check with a known time-of-check gap by a refusal before any process of the run exists, and leaves the race-free mechanism as the only one that admits such a contract. (2) removes the direct path to a declared model, including through an alternative DNS answer, at the cost of other destinations on that port; it adds no grant.

Options considered:
- Keep the supervisor's best-effort refusal at tier 1 and in the fanotify fallback (the earlier rule): every run starts, and a deliberate agent can write a hook through the race. Rejected: a protection that a sibling thread defeats is not one a record may call `refused`.
- The same, behind an explicit opt-in (a contract or machine key acknowledging best effort): keeps repository-root grants for users without root. Not built; it is the option to take if the cost below is too high, and it would need its own schema key and capability-line wording.
- Enumerate Landlock write grants around each target: refuses ordinary file creation above every target. Rejected (SEMANTICS §2).
- Drop the built-in set silently at tier 1: a silent loss of a default protection. Rejected (ADR 0002: missing features are reported, never silent).
- (2) keep refusing only resolved addresses, or honour `net.allow` naming a model: the bypasses above. Rejected.
- (2) identify the model on the port by TLS SNI: the supervisor does not read TLS, and encrypted ClientHello hides it. Rejected.
- (2) restrict the port only under a token or cost budget: the record would still claim the run's model traffic was captured. Rejected.

Consequence: The cost falls on users without root, or without a plane mode. A contract whose write entry contains a repository's `.git` (for example `fs.write` naming a repository root, with the contract kept outside it), a harness settings directory or a shell startup file no longer runs at tier landlock or with listener-only tier cgroup; it exits 125 naming the first target and the fix. `tego init`'s starter (`./out/`) and the shipped examples are not affected. A contract with a remote named model under forwarder capture and no `net:` section can no longer reach other services on the model's port (HTTPS on 443, typically) until a `net:` section names them. Stated residuals and conditions:
- Asymmetry: a `deny_read` target nested in a write entry, which Landlock cannot enforce at tier 1, still warns (`unenforced`) and runs, while a `deny_write` target now refuses the run. Whether `deny_read` should follow is a separate decision.
- A covering CIDR in `net.allow` that contains a model address gets no `model-direct-bypass` warning; the run refuses the address all the same.

Implementation (2026-10-03; recorded 2026-10-05): (1) `internal/runtime/enforce/select.go` (the pre-launch diagnostic), `internal/runtime/enforce/landlock/landlock.go` (`ErrNegativeWriteNeedsPlane`), the compile warning in `pkg/spec/agent/compile_denywrite.go`; tests `TestProtectedWritesRequirePlaneBeforeAnyRuleIsBuilt`, `TestSelectProtectedWritesRequiresActualPlane`, and the conformance landlock and listener axes, which expect exit 125. (2) `pkg/spec/agent/evaluate_models.go` (`GuardedModels`, `ModelPortRule`), `internal/policy/decide/net.go`, `internal/runtime/supervisor/models.go`; test `TestModelEndpointByName`. Neither rule had a dated Changes entry or a CHANGELOG line when it landed; enforce-landlock C7 and docs/CHANGELOG.md's Unreleased section now carry them.

*Amended 2026-10-05:* (2)'s "with or without a `net:` section" no longer holds. Later fixes made the port reservation apply only under a `net:` section: with none, the run refuses the model's resolved addresses and local aliases and, until its name has resolved, every destination on its port (`rule: unresolved`), and admits another address there `unmatched`; `compile`'s `model-port-restricted` warning is removed (SEMANTICS §1's 2026-10-05 note, supervisor R7, agent-contract E27). The Consequence's cost to a no-`net:` contract on 443 is gone with it, and an address only the agent's resolver returns reaches the model under no `net:` section (supervisor R7's Limit (a)); only a `net:` section closes that. The refusal of a model address that `net.allow` names, and the reservation under a `net:` section, stand as decided.

*Amended 2026-10-05 (ADR 0041 accepted, D1 decided (a)):* (1) no longer holds as the default. The option this ADR listed ("the same, behind an explicit opt-in") was chosen, the other way round: best effort is the default and the refusal is opted into with `fs.assurance: kernel`, which ADR 0041's 2026-10-05 note specifies and justifies. Without it, tier landlock and tier cgroup on its fanotify listener run a contract whose write entries reach built-in `deny_write` targets, the supervisor refusing writes to them on copied pathnames (supervisor R15c), with one `unenforced` compile warning per target and run_start `best_effort` `deny_write/default`; an over-capacity plane falls back to the listener again. With it, (1) holds as written, and compile reports it as an error at a pinned or machine-held tier landlock. The Consequence's cost to users without a plane, and the `deny_read`/`deny_write` asymmetry it lists, are gone with the default; the Why's race stands for the default and is what the disclosure names. enforce-landlock R5a and C8 carry it.
