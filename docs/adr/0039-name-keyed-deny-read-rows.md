# ADR 0039: name-keyed `deny_read` rows scoped to a subtree (PlaneNameDeny), a tier-3 strengthening

Status: accepted 2026-09-30 as a design; built through ADR 0043 (the kernel 2026-10-17, enforced in every build since 2026-10-27). Amends enforce-plane R5 and R25; states a tier-3 difference from SEMANTICS §2's glob rule.
Amended by ADR 0043: what a name entry decides (a whole `deny_read` entry at the object, creation included), how it matches (ASCII-folded, exact or literal prefix), its scopes and the climb that tests them, directory renames, compaction, the tiers and the capability; where the two differ, 0043 holds.

Context: a `deny_read` glob, the built-in `.env` scan included (agent-contract R6, up to 50,000 entries listed), is expanded at compile time to the files that exist then, one entry each (SEMANTICS §2: "files created later are not covered and `compile` says so"). At the plane each is a row keyed by its inode, so a project with many `.env` files passes the plane's 4096 rows (enforce-plane E13) or the launcher's descriptor budget (§2.4 condition 7) and runs at tier cgroup instead (§2.10 condition 2 as settled in P4). And a `.env` written after compile, by a tool of the user's while the run is live, is not denied at any tier.

Decision:
1. **A row kind keyed by a name, scoped to a subtree.** `PlaneNameDeny` rows live in a third per-slot inner map, `tego_plane_name_rows` (HASH_OF_MAPS by `run_idx`, like the exec rows; inner HASH, NO_PREALLOC, 64 entries a run), keyed by `tego_name_key` of an exact final name (`bpf/include/plane_name.h`, the key `bprm_check` and the fill already share). The value carries the name's bytes and length (compared with `tego_name_eq`, so a key collision matches nothing), the run's gen, the entry's `rule_idx`, and up to four scope inodes (pointer with `i_ino`, `i_generation` and `s_dev`, checked as an fs row's identity is, R6): the directories the glob was expanded under (the contract's directory and the run's cwd for the `.env` scan). Each scope is a keyed path, held by the Landlock plan and pinned by the domain like every other (ADR 0025 (3)).
2. **Where it decides.** `file_open` for a read, after the nearest-wins walk answered allow: when the slot's policy row says the run has name rows (one flag, so a run without them pays nothing), one name pass over the opened dentry's final name, one lookup, and, on a hit, whether any inode the walk already visited is one of the row's scopes. A hit refuses the read (`-EACCES`, reason `read-denied`, the glob entry's `rule_idx`): the name row acts as an entry at the object itself, depth 0, as the compile-time expansion's own entry at that path would. `path_rename` and `path_link` treat a source that matches a name row as read-denied for SEMANTICS §2's REFER rule, so the name cannot be renamed away from a file in the scope to read it under another. A name pass that cannot complete (the reader faults) refuses: the return discipline stays 0 or -EACCES (I2).
3. **What it covers.** Exact final names only (`.env`, `.env.local`, each its own row), no wildcard: a glob whose last component is not an exact name keeps today's expansion. A declared entry at a matched path (`fs.write: [./.env]`) is nearer and wins, as a declared path beats a glob's expansion today. The inode rows the expansion produces for the files that exist at compile time stay: they follow a file through a rename and a hard link made before the run; the name rows add the files created later and the ones past the plane's caps.
4. **Compile.** `decide.CompilePlane` emits name rows for the built-in `.env` scan and for any `deny_read` glob whose last component is an exact name, and then drops the per-file rows that a name row covers beyond the cap, so such a project stays at tier bpflsm. The root model (`RootIndex`, `Evaluate` at bpflsm) carries the name rows, so `TestPlaneRowsMatchEvaluate` holds them to the kernel's walk and `compile --test`'s bpflsm column predicts them.

The semantic difference, stated (SEMANTICS §2, "Globs in `deny_read`"): at tier bpflsm a name-keyed glob also denies a matching file **created after compile** beneath its scope; at tiers landlock and cgroup it does not. It is a **strengthening**: a name row only refuses reads and the renames and links that would read the same bytes under another name; it grants nothing and widens no rule. `compile --test` shows it as a cell where the bpflsm column says `deny` (the glob entry) and the landlock and cgroup columns say what the nearest entry allows; `compile` prints it on the glob's line, and the capability line of a tier-3 run says `deny_read.created_later: enforced`.

Why: [measured] a deny_read among many siblings holds every sibling at a descriptor, and tables of about 3,800 to 4,000 keyed paths met `EMFILE` at Prepare in the guest; P4 now refuses them naming the cap and runs auto at tier cgroup. [inference] The `.env` scan is the table most likely to be that large, and a name is how the contract states it. [documented] `tego_name_key` and `tego_name_eq` exist and are verified in `bprm_check` and the fill on 5.14, 6.1 and 6.17 (TIER3-PLAN T15, §6 E15), so the name pass's cost and its verification are known quantities.

Options considered:
- Widen the rows to a row per directory (§2.4's later change): covers existing files with fewer rows, but a directory row denies its siblings too, which the contract did not ask; and it still misses a file created later. Kept as the separate later change for globs that are not exact names.
- Raise the caps (rows 4096 to 65536, the launcher's `RLIMIT_NOFILE` hard limit as root): costs memory per slot and descriptors per run, and still misses files created later. Rejected as the answer for names; the budget is P4's.
- Match names at every step of the walk (a directory named `.env` denying its subtree): up to 64 name passes a read. Rejected for cost: the final component only; a directory's subtree is covered by the expansion's rows as today.
- Keep tier 3 equal to tier 1 here (no strengthening): simpler to explain, and leaves both the capacity and the created-later gap. Rejected: tiers 2 and 3 already decide more than tier 1 where the kernel can (the nested deny_read, SEMANTICS §2), and the difference is stated where the user reads verdicts.

Consequence: a project with more `.env` files than the plane holds runs at tier bpflsm; a `.env` written during the run beneath the project is unreadable to the agent at tier 3 (its own write of one goes ahead, a write is not a read; reading it back is refused unless the contract names that path in `fs.write`). Name rows cost one bounded name pass and one lookup per read open in a run that has them. Tests, when built: the name rows held to the model by `TestPlaneRowsMatchEvaluate`; root cells in the guest for a file created during the run and for a rename away from a name row; a `compile --test` cell showing the bpflsm column's difference.

Adversarial review note, 2026-09-30:
- *A case-insensitive directory (casefold ext4, vfat, exFAT) opens `.ENV` as `.env`'s file under another spelling.* The name bytes compare exactly, so the name row misses it. The compile-time inode rows still cover files that existed; a file created later under another case is the residual. Stated as a condition: `compile` warns when a scope lies on a filesystem that can fold case (the same finding SEMANTICS §2 states for `deny_write` names).
- *A hard link made before the run to a later-created `.env`.* A link made before the file exists cannot name it; a link made during the run to a name row's file is a `path_link` of a read-denied source, refused under REFER.
- *A recycled scope pointer.* The scope is pinned by the domain and carries `i_ino`, `i_generation` and `s_dev`, compared as an fs row's (R6); a mismatch is no scope, and a read under it falls to the walk's own answer, which is never looser than the contract's entries.
- *Two runs, one name map.* Per slot and gen, like the fs and exec rows (R6): another run's rows are absent to this one.
- *The name pass costs every read.* Only in a run with name rows (the policy flag), and bounded by `TEGO_NAME_WORDS` bpf_loop steps; measured at implementation, with a go condition: at most 1 µs added to an open's p50 on 6.17 in the guest.
- *Prediction drift.* The row compiler and `Evaluate` answer from one model (ADR 0028), and the rows are held to it by `TestPlaneRowsMatchEvaluate`; a name row the model lacked would fail it.
- *An agent that writes a `.env` for its own tests and reads it back breaks at tier 3 only.* Accepted as the strengthening's cost; the contract's way out is a declared entry at that path, which is nearer, and `compile --test` shows the difference before the run.
