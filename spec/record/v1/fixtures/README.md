# Record v1 fixtures

Frozen with record v1. Every view in `internal/check` is built against these files; CI replays them.

| File | What |
|---|---|
| `run-fixture.jsonl` | One realistic run of the `retriever` agent (a Python agent): 20 model steps through the forwarder with one `tool_use` decision each, tool execs (`rg`, `git`, `cat`, `gh`, `python3`), aggregated reads, writes under `./out`, an MCP server, one refusal (`read-denied` on `~/.ssh/id_ed25519`), a capture gap (`gh`, a static Go binary), a record gap (12 dropped events), a token limit and `run_end reason=limit`. Actions inside a step carry `{likely, time, step N}`; startup actions are `{unattributed, none}`. |
| `chain.log` | The anchor line for that run: `<run> <head>`, `head` being the `run_end` line's id. |
| `kinds.jsonl` | One valid line per v1 kind, all fifteen (`ask`, `answer`, `boundary` included), as one short chain. |
| `harness.jsonl` | A run at `record_minor` 14 whose launcher provisioned Claude Code (agent-contract.md R27, ADR 0062): `run_start.harness` with its file, reason file and hook-state directory, `runtime_grants` naming `fs.harness-state[...]`, one write that grant allowed, one refused write to the provisioned settings file, `run_end`. Written by `internal/ledger`'s `TestHarnessFixtureFrozen` (`-update` regenerates it); `pkg/spec/record`'s `TestHarnessFixture` reads it through `Decode`, `Validate` and `Chain`, and `internal/check/viewtest`'s `TestViewsReadHarnessFixture` through every view. |
| `profiles.jsonl` | A short run at `record_minor` 15 whose `run_start.profiles` lists the profiles its contract merged, in merge order (`tego/python` built in, then `base` and `team` from the profiles directory; ADR 0066 D6): run_start, one write, run_end. |
| `profiles.chain.log` | The anchor line for that run. |
| `user-deny-write.jsonl` | A short run at `record_minor` 19 (`MinorUserDenyWrite`, ADR 0071) whose contract declares `fs.deny_write: [./deploy/]` beside the write entries `./` and `./deploy/tmp/`: `run_start.best_effort` lists `fs.deny_write` (and, as every `run_start` at 17 and 18 or later, `launcher_uid` and `fs_reads`, here `direct` with no nested target), a write of `deploy/ci.yml` is refused `fs.deny_write[./deploy/]` by the supervisor with its `refused` line, and a write in the reopened `deploy/tmp/` is allowed under that write entry. Written by `internal/ledger`'s `TestFixturesFrozen`; `pkg/spec/record`'s `TestUserDenyWriteFixture` reads it. |
| `host-sockets.jsonl` | A short run in ADR 0070's unix-only state (no `net:` section, record minor 16): connects to the Docker daemon's socket (its `net` line's `what` names what it gives) and to an abstract name the run does not hold, each refused `host-sockets` with its `refused` line; the run's own socket under its write entry and an IP destination allowed. |
| `run-identity.jsonl` | A short run at `record_minor` 17 (`MinorRunIdentity`, ADR 0073) whose `run_start` carries every run identity key: a root launcher (`launcher_uid` 0) under sudo (`sudo_uid` 1000, `sudo_user` u), its `host`, a `parent_run`, two `labels`, `role` check and a `contract_revision`: run_start, one write, run_end. |
| `run-identity.chain.log` | The anchor line for that run. |
| `held-reads.jsonl` | A short run at tier landlock and `record_minor` 18 whose reads were held (ADR 0069): `run_start.fs_reads` is `held`, why `nested`, naming the `.env` the compile's scan found inside `fs.write ["./out/"]`, with the deny_read capability rows and the `launcher_uid` every `run_start` at 17 or later carries; the agent's `cat out/.env` is refused `read-denied` by that entry and its `cat out/.env.local` of a file made during the run by the built-in name rule, each one `fs` line from `seccomp` (the supervisor answered on the object the open deputy reached); the allowed read of `out/src/a.txt` has no line under `record: summary`. |
| `held-reads.chain.log` | The anchor line for that run. |
| `reason-reads.jsonl` | A short run at tier landlock and `record_minor` 23 under `record: summary` whose read opens were told to the supervisor for the reason channel (ADR 0077): `run_start.reads_notified` is notified, why `reason`, and `fs_reads` direct, `none-nested`; the agent's `cat ~/.ssh/id_ed25519` is one `fs` line from `seccomp`, refused `read-denied` under `fs.deny_read[~/.ssh]` with `mechanism: landlock` (the supervisor continued the open and Landlock refused it), and its `refused` mirror carries `mechanism: landlock` too; the allowed read of `out/a.txt` has no line. |
| `reason-reads.chain.log` | The anchor line for that run. |
| `live-block.jsonl` | A run at `record_minor` 21 (`MinorLiveBlock`) in which a person blocked a program and a destination live (`live-block-added`), each refused under its `live.block[<kind>:<value>]` rule, then removed both (`live-block-removed`), after which the contract's own entries allowed them; and one overlay the launcher could not read. Written by `internal/ledger`'s `TestLiveBlockFixtureFrozen`; `pkg/spec/record`'s `TestLiveBlockFixture` and `TestLiveBlockFixtureValidatesAt` read it. |
| `live-control.jsonl` | A run at `record_minor` 24 (`MinorLiveControl`) under `record: full`: a read block of `.env` from the dashboard and a write block of `src/` from the CLI, each refused under `live.block[read:...]` or `live.block[write:...]` with its `refused` mirror while a read in `src/` stays allowed; then a pause and a resume (`run-paused`, `run-resumed`), and a pause the launcher could not apply (`pause-failed`) followed by its resume (`run-resumed`), each with `live_control`. Written by `internal/ledger`'s `TestLiveControlFixtureFrozen` (`-update` regenerates it); `pkg/spec/record`'s `TestLiveControlFixture` reads it through `Chain` and `ValidateAt`. |
| `live/valid/*.json`, `live/invalid/<code>.*.json` | Documents `{"kind", "minor", "rule", "payload"}` (`rule` on a `refused` line only): the live changes' rules (`live_block`, `live_control`, the pause whys and the `read` and `write` kinds). Each valid one passes `Event.ValidateAt(minor)` and `MarshalLineAt`; each invalid one is refused by both with the code its name starts with (`TestLiveFieldFixtures`: `below-minor`, `field-case`, `live-block`, `live-control`). Hand-made, not generated. |

The files are generated, not hand-written: `internal/ledger`'s `TestFixturesFrozen` writes the run through the
real `Writer` with a scripted clock and compares the bytes; `go test ./internal/ledger -run TestFixturesFrozen
-update` regenerates them. `pkg/spec/record`'s `TestRunFixture`, `TestKindsFixture` and `TestHostSocketsFixture` verify every line
through `Decode`, `Validate` and `Chain` alone, `TestProfilesFixture` the profiles run,
`TestRunIdentityFixture` the run identity run, `TestHeldReadsFixture` the held-reads run and `TestReasonReadsFixture` the
reason-reads run; `test/fixtures` replays `run-fixture.jsonl`, `profiles.jsonl`, `run-identity.jsonl`, `held-reads.jsonl`
and `reason-reads.jsonl` through every view.

Reading rules the fixtures exercise: `id` = sha256 of the line with `id` set to 64 zeros; `prev` chains ids;
`seq` is gapless; `rule` and `reason` appear once, in their canonical slot, on `refused`, `limit` and `run_end`
lines as well as on actions. Ledgers are never rewritten; these files must not be edited by hand.
